# Доменная документация

Как скиллы должны читать документацию этого репозитория, когда разбираются в кодовой базе.

## Перед разведкой прочитай это

- **`docs/wiki/глоссарий.md`** — словарь проекта: имена предметной области и запрещённые синонимы.
  Корневой `CONTEXT.md` — только указатель на него, терминов там нет.
- **`docs/wiki/index.md`** — каталог живого слоя: страница на подсистему. Текущее устройство
  подсистемы бери оттуда, а не выводи из кода с нуля; `docs/wiki/константы.md` — единственный дом
  каждого настраиваемого числа.
- **`docs/adr/`** — читай ADR, затрагивающие область, в которой собираешься работать.

Каталога `docs/adr/` пока нет, и это нормально: если чего-то из перечисленного не существует —
**молча продолжай**. Не сообщай об отсутствии и не предлагай завести заранее. Скилл
`/domain-modeling` (через `/grill-with-docs` и `/improve-codebase-architecture`) заводит их лениво,
в момент, когда термин или решение реально разрешены.

## Структура файлов

Репозиторий **single-context** (монорепо-признаков нет):

```
/
├── CONTEXT.md              ← указатель на глоссарий
├── docs/
│   ├── wiki/               ← живой слой: состояние подсистем + глоссарий + константы
│   └── adr/                ← появится с первым труднообратимым решением
├── log.md                  ← append-only хронология
├── scripts/                ← GDScript: матч, ИИ, стандарты
└── src/                    ← C#: ядро порта GameplayFootball
```

## Пиши словарём глоссария

Когда результат называет доменное понятие (заголовок тикета, предложение по рефакторингу,
формулировка гипотезы, имя теста) — бери термин в том виде, как он определён в
`docs/wiki/глоссарий.md`. Не соскальзывай в синонимы, которые глоссарий явно запрещает: у этого
проекта две истории (собственный прототип на GDScript и порт ядра GameplayFootball на C#), и
половина запретов родилась из того, что одно понятие называлось по-разному в этих двух мирах.

Понятия нет в глоссарии — это сигнал: либо ты придумываешь язык, которым проект не пользуется
(передумай), либо есть реальный пробел (отметь его для `/domain-modeling`, дописывать термины
надо в `docs/wiki/глоссарий.md`, не в `CONTEXT.md`).

## Сообщай о конфликте с ADR

Если результат противоречит существующему ADR, скажи об этом явно, а не переписывай молча:

> _Противоречит ADR-0007 (…) — но стоит переоткрыть, потому что…_

Пока `docs/adr/` пуст, ту же роль несут `log.md` (записи типа `решение`/`decision`) и датированные
спеки в `docs/superpowers/specs/` — они не редактируются, и противоречие им сообщается так же.
