# 02 — Конвейер `.ase` → `.glb` и проверка геометрии стадиона

**What to build:** воспроизводимая сборка геометрии стадиона из версионированных `.ase` в `.glb`, и
headless-проверка, которая ловит ошибку конвейера цифрами, а не глазами.

Конвертируются `test.ase` (стадион, 1642 GEOMOBJECT, 31 материал), `pitch.ase` (4 квадранта),
`goals.ase`, `generic.ase` (мяч). Парсер конвейера расширяется секцией `MESH_NORMALS` и привязкой
материалов: каждому мешу в `.glb` — именованный слот материала по `MATERIAL_REF`. Карты и скаляры
материалов конвейер не читает — их в рантайме читает загрузчик лабы (тикет 03). `.glb` несёт только
геометрию и имена материалов; текстуры не запекаются — иначе генератору газона некуда писать.

Объекты клеятся по материалам: один меш на материал, дробить только по технической необходимости
(`SplitGeometry` оригинала — движковый CPU-куллинг, не портируется). Позиции узлов
(`TM_POS`/`TM_ROW3`) игнорируются — вершины уже в мировых координатах. ODE-коллизия из `.object`
игнорируется — отскок от земли считает `Gpf.Ball`. Автоконверсия осей Blender/glTF подавлена:
вершины остаются в координатах оригинала (X — длина поля, Z — вверх), прецедент проверки —
`check_gpf_blockout`.

Сюда же — данные рамки поля в `GpfPitch` (`pitchFullHalfW = 60`, `pitchFullHalfH = 40`,
`gamedefines.hpp:273-274`): без них не считается генератор газона и не проверяется рамка.

«Воспроизводимо» = повторный прогон на той же версии Blender (фиксируется в шапке скрипта) даёт
`.glb`, проходящий проверку; побайтовая идентичность не требуется.
