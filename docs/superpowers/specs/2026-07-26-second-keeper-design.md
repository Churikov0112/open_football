# Второй вратарь (team_1) + обобщение singleton `_keeper` — дизайн

**Дата:** 2026-07-26
**Статус:** согласован, готов к плану реализации.
**Тип:** фундаментальный рефактор + фича (предшествует ИИ-удару от ворот, пункт #6 Этапа 2
роадмапа оркестрации `2026-07-22-match-orchestration-roadmap-design.md`).

## Что это и зачем

Сейчас в матче **один** вратарь — team_2 в воротах Home (−Z), которые атакует человек. Ворота
team_1 (Away, +Z) пустые. Это блокирует симметричные стандарты: удар от ворот для team_1 некому
исполнять, пенальти/штрафной в ворота team_1 некому защищать. Пока роадмап двигался по стандартам
для team_2, это не мешало, но **ИИ-удар от ворот (#6)** первым упирается в проблему: судья при уходе
мяча за лицевую team_1 присудит удар от ворот team_1, а бьющего (вратаря) нет.

`keeper_ai.gd` **уже полностью сторона-агностичен** — вся геометрия выводится из параметра
`goal_line_z` (паттерн `into := -1.0 if goal_line_z > 0.0 else 1.0`), ни одного хардкода
`team_2`/`-Z`. Значит второй вратарь едет на том же коде. Мешает **не ИИ, а singleton `_keeper`**:
поля `_keeper`/`_keeper_brain` (одиночные) зашиты в 29 местах менеджера и во всех сет-пис
контроллерах (36 ссылок в пенальти, 12 в штрафном, 11 в ударе от ворот, 10 в угловом).

**Цель:** добавить вратаря team_1 в ворота Away и обобщить singleton `_keeper` в per-goal резолв,
чтобы каждый стандарт находил «вратаря нужных ворот». Матч становится симметричным; team_1 получает
живого голкипера; открывается дорога к ИИ-удару от ворот и защите team_1 на пенальти/штрафных.

## Ключевые решения

- **Подход A — на ростере/группах, без singleton.** `Team.keeper()` (метод ростера) уже существует
  и фактически дублирует `_keeper`. Убираем поля `_keeper`/`_keeper_brain` целиком; вратарей
  резолвим через ростер и группу `role_gk`.
- **Резолв по `goal_line_z`, без хардкода стороны.** Хелпер `_keeper_at(goal_line_z)` выводит
  защищающую команду из `attack_z_sign`, а не из литералов `team_1`/`team_2` или знака Z.
- **`keeper_ai.gd` не трогаем** — он уже сторона-агностичен. Работа — в менеджере и контроллерах.
- **Дебаг-клавиши не меняют цель** — остаются на −Z (team_2-вратарь), чтобы существующий тест-флоу
  не сдвигался. team_1-вратарь проверяется реальной игрой.

## Архитектура

### Спавн двух вратарей

`_setup_keeper()` обобщается в `_setup_keeper(team: Team, goal_line_z: float, kit_color: Color)`
и вызывается дважды из `_ready`:
- **team_2** → `-field_length` (GoalHome, −Z), зелёный `Color(0.15, 0.7, 0.15)` — как сейчас;
- **team_1** → `+field_length` (GoalAway, +Z), оранжевый `Color(0.85, 0.55, 0.1)` — новый, чтобы два
  вратаря визуально различались между собой и от полевых.

Каждый вратарь получает свои keeper-специфичные узлы (`SaveArea`, `HoldPoint`), создаваемые в
`_setup_keeper` после `PlayerFactory.spawn` (как сейчас). Позиция/линия/дайв — из `goal_line_z`
(код уже это умеет). Каждый защищает ворота, которые атакует **соперник**: team_1-вратарь в
GoalAway парирует атаки team_2-ИИ (человек получает голкипера в своих воротах); team_2-вратарь в
GoalHome парирует атаки человека (без изменений).

### Резолв вратаря (замена singleton)

Поля `_keeper: CharacterBody3D` / `_keeper_brain: Node` **удаляются**. Вводится хелпер на менеджере:

```
func _keeper_at(goal_line_z: float) -> CharacterBody3D:
    # Вратарь команды, ЗАЩИЩАЮЩЕЙ ворота у goal_line_z.
    # Защищающая команда = та, чей attack_z_sign == -signf(goal_line_z)
    #   (team_1 attack -Z → защищает +Z; team_2 attack +Z → защищает -Z).
    # Возвращает team.keeper() (ростерный метод, уже есть). null если вратаря нет.
```

Резолв выводится из `attack_z_sign` ростера — без хардкода стороны/команды. Для −Z вернёт
team_2-вратаря, для +Z — team_1-вратаря.

### Инвариант referee tdn

Строка `tdn := 2 if _keeper.is_in_group("team_2") else 1` (выводила защищающую −Z команду из
единственного вратаря) заменяется на прямой вывод из ростера: команда, защищающая −Z = та, у кого
`attack_z_sign > 0` (т.е. team_2 при текущей расстановке). Singleton больше не участвует.

## Точки касания (замена 29 ссылок менеджера + контроллеры)

### Контроллеры — резолв в `start()`, а не `setup()`

Единый вратарь передавался в `setup(...)` при `_ready` и кешировался. С двумя вратарями нужный
резолвится **в момент розыгрыша**:
- `setup(...)` четырёх контроллеров **теряет параметр `keeper`** (менеджер больше не передаёт
  единого вратаря; сигнатуры вызовов в `_ready` обновляются).
- В `start(kicker, goal_line_z, ...)` контроллер сам ставит:
  `_keeper = _manager._keeper_at(goal_line_z)`, `_keeper_brain = _keeper.brain()`.
- **Внутренние ссылки контроллеров не трогаются** (36 в пенальти и т.д.) — они читают собственный
  кеш `_keeper`/`_keeper_brain`, просто наполненный из правильного источника.
- **Удар от ворот — особый случай:** бьющий = сам вратарь (передаётся в `start` как `kicker`), не
  защищающийся. Поэтому goal_kick ставит `_keeper = kicker; _keeper_brain = kicker.brain()`
  (не `_keeper_at`).

Каждый контроллер держит собственные `_keeper`/`_keeper_brain` — гейм/презентейшн-сплит вратаря
(`_keeper` = тело для freeze/идентичности, `_keeper_brain` = API/состояние) сохраняется как есть.

### Заморозка / сброс / контакт — по группе `role_gk`

- **`_set_ai_frozen(on)`** — пропускает всех членов группы `role_gk` (оба вратаря всегда
  самоуправляемы). Аргумент-исключение `_keeper` уходит; вызовы (строки 535, 750, 2147)
  обновляются.
- **Подбор бесхозного мяча `_handle_dribbling()`** (строка 1251, ЖИВОЙ — каждый кадр) — пропускает
  `role_gk` вместо `p == _keeper`, чтобы team_1-вратарь не «подбирал» бесхозный мяч у своих ворот
  как полевой.
- **`_reset_ball()`** (строка 2100, сейчас мёртвый — нигде не вызывается, но правим для
  корректности) — репозиционирует `_team_home.players() + _team_away.outfield()`; `players()`
  включает team_1-вратаря, из-за чего его бы сбрасывало с линии. Меняем на
  `_team_home.outfield() + _team_away.outfield()` (оба вратаря исключены, как team_2 и раньше).
- **Контакт с мячом** (строки 2077–2079): `if body.is_in_group("role_gk") and body.brain() != null
  and body.brain().has_method("on_ball_contact"): body.brain().on_ball_contact()` — диспетч на
  того вратаря, что коснулся (ловля работает у обоих; идентичность по группе, не по singleton).

### Дебаг-клавиши (P/K/F/C/G)

Остаются целящими в −Z (team_2-вратарь), как сейчас, — существующий тест-флоу не меняется. Резолв
цели: `_keeper_at(-field_length)` вместо `_keeper_brain.goal_line_z`. Проверка гейта `_keeper != null`
заменяется на `_keeper_at(-field_length) != null`. Гол/пенальти/штрафной/угловой в ворота team_1
через дебаг-клавиши в этой задаче НЕ добавляются (это ИИ-стандарты Этапа 2 / будущая
диспетчеризация).

## Границы задачи (что НЕ входит)

- **ИИ-удар от ворот** (планировщик `AIGoalKickIntent`, авто-диспетч судьёй) — следующая задача,
  ради которой этот фундамент и делается. Здесь только вратарь + обобщение.
- **Авто-диспетчеризация стандартов судьёй** — вне этой задачи (остаётся по дебаг-клавишам).
- **ИИ-защита team_1-вратаря на пенальти/штрафном человека-соперника** — инфраструктура (два
  вратаря, резолв) готовится здесь, но новых боевых путей защиты не добавляется; team_1-вратарь
  работает своей обычной реактивной логикой в открытой игре.
- **Второй вратарь как human-actor** (человек играет вратарём team_1) — не здесь.

## Тестирование

Паттерн проекта (headless `tests/check_*.gd`, чистые функции без автолоада):
- **`check_two_keepers.gd`** (headless-смоук): оба вратаря спавнятся у своих ворот с правильным
  `goal_line_z` (−/+field_length); `_keeper_at(-field_length)` возвращает team_2-вратаря,
  `_keeper_at(+field_length)` — team_1-вратаря; группа `role_gk` содержит ровно двоих; `_reset_ball`
  не сдвигает ни одного вратаря с линии.
- **Существующие `check_keeper_logic.gd`/`check_keeper_clear.gd`/`check_penalty_*`/`check_goal_kick_*`
  остаются валидны** — ИИ вратаря сторона-агностичен, сет-пис флоу-тесты зовут контроллеры напрямую.
  Прогнать после рефактора, диффать по категориям.
- **Baseline-валидация сцены** — обе headless-команды из CLAUDE.md (menu-load + `match.tscn`), дифф
  по категориям ошибок (`!is_inside_tree()`, `states.has(p_name)`, transition-duplicate,
  `WorldEnvironment3D`), не по числу.
- **Фил** (team_1-вратарь реально тащит атаки team_2, корректно ловит/выбивает у своих ворот, не
  мешает человеку) — только человек за игрой; headless не драйвит рендер/физику приземления.
