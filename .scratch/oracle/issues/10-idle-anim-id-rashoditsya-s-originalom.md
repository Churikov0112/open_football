# 10 — `GetIdleMovementAnimID` в порте выбирает не тот клип, что оригинал

Status: needs-triage
Type: bug

**Найдено оракулом** при приёмке тикета 03 (первое сведение трасс, 2026-08-04). Ретроспективная
находка по фазам 1–3: код написан и принят человеком, ошибку не поймали ни компилятор, ни 25
headless-тестов, ни глаз.

**Симптом.** На **нулевом тике**, до всякой динамики, обе стороны стоят на своём idle-клипе кадра 0 —
и клипы разные:

```
эталон  P,0,26,1,movement/idle/000_idlelevel1,1128,movement,1,0,-1,0,0,0,9.473575,1.655500,...
порт    P,0,0, 1,autogen [v0 b0] => [v0 b0 a0]_mirror,512,movement,1,0,-1,1,0,0,9.473575,1.655500,...
```

Позиция, угол, кадр, `enum_velocity`, `quadrant_id` и оба смаггла совпадают до знака: стартовое
состояние поднялось верно. Расходятся ровно три поля, и все три — следствие одного выбора:
`anim_name`, `anim_id` и `foot` (у клипа эталона исходящая нога левая, у клипа порта правая).

**Манифесты при этом совпадают побайтово** — 1452 клипа, тот же порядок, те же имена, ноги и длины.
Значит дело не в загрузке коллекции и не в нумерации: `anim_id` 1128 и 512 указывают на разные
клипы в **одинаковых** коллекциях. Это ошибка в логике отбора, а не в данных.

**Причина по коду.** Правила разные.

Оригинал (`humanoidbase.cpp:875-947`) делает полноценный отбор: `CrudeSelection` по
`functionType = Movement`, `incomingVelocity = Idle`, `outgoingVelocity = Idle`, затем цепочка
`std::stable_sort` — сперва по близости числовой переменной `idlelevel` к 1
(`SetNumericVariableSimilarityPredicate("idlelevel", 1)`), потом по схожести входящего направления
тела с `(0, -1, 0)`, и дальше по остальным предикатам.

Порт (`AnimCollection.cs:130-138`) берёт первый попавшийся:

```csharp
for (int i = 0; i < _animations.Count; i++)
{
    var a = _animations[i];
    if (a.GetAnimType() == "movement" && a.GetIncomingVelocity() < 1.8f && a.GetOutgoingVelocity() < 1.8f)
    {
        _idleMovementAnimId = i; // фолбэк humanoidbase.cpp:1416
        break;
    }
}
```

Комментарий в порте ссылается на `humanoidbase.cpp:1416` — но там `GetIdleMovementAnimID()` только
**вызывается** как фолбэк, а сама функция живёт на `:875`. То есть портирована ссылка на место
вызова, а не тело. Первым в коллекции идёт автоген (`GenerateAutoAnims` стоит до файлового цикла),
поэтому порт и получает `autogen [v0 b0] => [v0 b0 a0]_mirror` с индексом 512 вместо файлового
`movement/idle/000_idlelevel1`.

**Почему это важно, а не косметика.** `GetIdleMovementAnimID()` — не только стартовый клип:
`humanoidbase.cpp:1416` подставляет его как **аварийный фолбэк отбора**, когда подходящего клипа не
нашлось (после странных столкновений, падений, невозможных углов тела). Каждое такое срабатывание
уводит порт на другой клип, с другой ногой и другим движением корня.

**Чинить не сейчас.** Фаза 5 измеряет, а не чинит (правило спеки). Тикет заводится, чтобы ошибка не
потерялась; порядок починки — за человеком.
