# Глоссарий

Имена предметной области и **запрещённые синонимы**. Термин берётся отсюда для заголовков задач,
имён тестов, сообщений коммитов и формулировок гипотез. Разрешил новый термин — допиши сюда.

Здесь только *как это называется*; *как это работает* — на странице подсистемы по ссылке. У проекта
две истории (собственный прототип на GDScript и порт ядра GameplayFootball на C#), и большая часть
запретов ниже родилась из того, что одно и то же понятие называлось по-разному в этих двух мирах.

## Ядро матча

**Мозг**: дочерний `Brain`-компонент игрока, несущий ИИ; тело — `CharacterBody3D`, мозг читает его
через `_body`, не через `self`. Отдельно и единственно — «один мозг» про `match_manager.gd`,
владеющий матчем целиком. [[архитектура]], [[фабрика-игроков]]
_Avoid_: «ИИ-скрипт на игроке», «скрипт тела», `set_script` — ИИ никогда не навешивается на тело.

**Чистая математика**: класс без autoload и без чтения `FootballConstants`, тюнингуемый только
параметрами (`PassSystem`, `NetSim`, `KeeperLogic`, `PenaltyLogic`, `RefereeLogic`, статика
`PlayerMotor`). [[архитектура]]
_Avoid_: «хелпер», «утилита», «синглтон» — последнее прямо противоречит инварианту.

**Baseline ошибок**: известный набор ошибок сцены матча в headless-прогоне, который диффается по
**категории и тексту**, не по счётчику. [[архитектура]], [[конвенции]]
_Avoid_: «ошибки headless», «число ошибок» — счётчик плавает и ничего не доказывает.

## Мяч и действия

**lead-follow**: модель дриблинга — мяч ведётся к точке впереди игрока на дистанции, растущей со
скоростью. [[мяч-и-дриблинг]]
_Avoid_: «пружина», «spring», `SPRING_*`, «velocity-matching» — легаси прошлых моделей, живущее
только в OPENCODE.md; описанию пружины там верить нельзя.

**deferred-impulse** (он же commit-action): удар и пас применяются отложенным импульсом через
`ActionExecutor` по кадру `action_contact` анимации. [[пас]], [[удар]]
_Avoid_: «прямой удар», «вызвать `ball.kick()`» — прямой вызов из геймплея запрещён.

**Break-away**: мяч ушёл дальше `DRIBBLE_CHASE_DIST` и катится свободно, владение сохраняется, идёт
догон. [[мяч-и-дриблинг]]
_Avoid_: «потеря мяча», «отбор» — владение теряется только внешне (подкат/перехват).

**intent-шов**: per-actor слой намерения на стандартах — человек и ИИ поставляют одинаковый интерфейс
намерения, контроллер стандарта их не различает. [[стандарты-и-intent-seam]]
_Avoid_: «контроллер решает», «ветка для игрока» — ветвления по «человек/ИИ» в контроллерах нет.

## Порт GameplayFootball

**Клип**: единица анимации порта — файл `.anim` из `assets/gpf/` со своим форматом (CSV-треки +
`extension` + XML-хвост). [[порт-gameplayfootball]]
_Avoid_: голое «анимация» — в проекте параллельно живут Mixamo-клипы презентации через
`AnimationTree`; уточняй, о каком мире речь. [[презентация-и-ассеты]]

**Варпинг**: подгонка траектории выбранного клипа под физику игрока (`PhysicsVector.Calculate`,
порт `CalculatePhysicsVector`). [[порт-gameplayfootball]]
_Avoid_: «блендинг», «root motion», «ретаргет» — это другие механизмы, здесь их нет.

**Смаггл** (smuggle): скрытая доводка позиции/поворота тела поверх клипа, которой оригинал прячет
рассинхрон анимации с физикой. [[порт-gameplayfootball]]
_Avoid_: «коррекция», «подтяжка», «доводка» — расходятся с именем поля в коде и в C++ оригинале.

**Квадрант**: одна из 34 корзин `AnimCollection` (idle + 3 скорости × 11 углов), по которой клип
находится при отборе. [[порт-gameplayfootball]]
_Avoid_: «бакет» — бакеты это квантование скорости (`BucketVelocity`), другая сущность с другими
границами.

**Палочник** (stickman): отрисовка 14-костного скелета порта линиями — левая сторона красная, правая
синяя. [[порт-gameplayfootball]]
_Avoid_: «модель», «персонаж» — Mixamo-моделей в лабах нет.

**Лаба**: отдельная сцена под `scenes/lab/` для проверки порта глазами (`anim_lab`, `walk_lab`,
`ball_lab`); к `match.tscn` отношения не имеет и живёт на своём тикрейте. [[порт-gameplayfootball]]
_Avoid_: «тестовая сцена», «демо» — headless-тесты это `tests/check_*.gd`, совсем другой жанр.

**Эталон-exe**: собранный оригинальный GameplayFootball, к ощущению которого приводится порт.
[[порт-gameplayfootball]]
_Avoid_: «оригинал» без уточнения — «оригиналом» в тексте порта зовут и C++ исходники, и бинарник;
для исходников пиши «C++ оригинал».

**bug-for-bug**: сознательный перенос ошибки оригинала без починки, чтобы поведение совпадало.
[[порт-gameplayfootball]]
_Avoid_: «баг порта», «недоделка» — каждое такое место помечено в коде комментарием и правке не
подлежит.
