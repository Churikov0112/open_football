# Живая локомоция — дизайн (спек №1 из этапа «По-взрослому»)

**Дата:** 2026-07-09
**Ветка:** `feat/living-locomotion`
**Статус:** дизайн утверждён, готов к плану реализации

## Контекст и цель

Этап 8 «По-взрослому» из [3d-assets-pipeline-design](2026-07-08-3d-assets-pipeline-design.md) — это
четыре независимых столпа реализма движения (root motion, motion matching, foot IK,
physics/ragdoll-blending). Этот спек — **первый и самый крупный по постоянной видимости** кусок:
базовая «живость» локомоции.

**Планка реализма — «не выглядеть дёшево».** Не паритет с FIFA (соло недостижим из-за объёма
мокап-данных, не из-за движка), а устранение явных «дешёвых» тэллов, которые видно в каждую
секунду игры. Motion matching и полноценный foot IK для этой планки **избыточны** и в спек не
входят.

### Что сейчас читается как «дёшево» (по коду)

1. **Мгновенный разгон и стоп.** [`match_manager.gd:541-545`](../../../scripts/match/match_manager.gd) —
   скорость `8.0` применяется через `move_toward` по позиции без разгона: из стойки в полный бег за
   1 кадр и так же мгновенно стоп. Виден постоянно.
2. **Скольжение стоп в беге.** [`player_visual.gd:84-86`](../../../scripts/player/player_visual.gd) —
   клип `run` играется с фиксированной скоростью независимо от реальных м/с, ноги «подметают» землю.
3. **Пивот на месте при развороте.** Поворот сглажен `lerp_angle` (10/с), но клип тот же бег — тело
   крутится, ноги едут боком. У ИИ вообще мгновенный снап ([`match_manager.gd:589`](../../../scripts/match/match_manager.gd)).

## Референс: рецепт «отличного фила» из OpenSoccer

`C:\Users\User\Desktop\OpenSoccer` (соседний проект того же автора, играется отлично). Разбор
[`Player.gd`](file:///C:/Users/User/Desktop/OpenSoccer/Scenes/Player.gd) показал: его «фил» — **не**
foot IK и **не** motion matching, а пять простых ручных приёмов + тюнинг:

1. **Движение через скорость + инерцию, а не позицию:** `velocity += acc*pAcc` →
   `velocity.limit_length(pSpeed)` → `move_and_slide()` → `velocity *= inertia` (0.94). Отпустил ввод
   — скорость плавно гаснет (глайд); нажал — плавный разгон.
2. **Запаздывающий сглаженный разворот:** взгляд вдоль вектора `view`, который сам slerp'ится, а
   трансформ ещё и `transform.interpolate_with(newt, delta*18)`. Два слоя сглаживания, ноль снапов.
3. **Наклон корпуса в поворот (banking):** `lean = acc.dot(basis.x)` наклоняет `up`-вектор в сторону
   бокового ускорения, масштабируя по скорости.
4. **Скорость анимации привязана к реальной скорости:** `rspeed = vl/pOSpeed*1.33` → `RunSpeed/scale`.
   Это и есть анти-слайд стоп.
5. **Стейт-машина по порогам скорости:** idle / walk / sprint / sprinthard через `travel()`.

Foot IK там нет вообще. Физические кости (`PhysicalHips`) — только под хит-реакции (наш будущий
спек №2 «Ragdoll»).

**Решение:** перенести этот рецепт в архитектуру OpenFootball. Ядро — миграция локомоции с
direct-position на velocity+inertia; сверху — сглаживание разворота, banking и анти-слайд.

## Архитектура: компонент `PlayerMotor`

Рецепт движения сейчас пришлось бы дублировать в трёх местах (`match_manager` + `simple_ai` +
`teammate_ai` — все двигают `global_position` напрямую:
[`simple_ai.gd:100`](../../../scripts/ai/simple_ai.gd),
[`teammate_ai.gd:62`](../../../scripts/ai/teammate_ai.gd)). Вместо дублирования — **один общий
компонент**.

**`PlayerMotor`** (`scripts/player/player_motor.gd`, `class_name PlayerMotor`) навешивается на каждый
полевой `CharacterBody3D` рядом с `PlayerVisual`.

- **Владеет** всей физикой движения: velocity + инерция + `move_and_slide()`, сглаживание разворота,
  banking, и кормит `PlayerVisual` (скорость → анти-слайд + бленд + крен).
- **Публичный API — единственный шов:**
  - `set_move_intent(dir: Vector3, speed_scale := 1.0)` — желаемое направление в мировых координатах
    (нормализуется внутри); `speed_scale` — задел под спринт/замедления.
  - `set_control_locked(on: bool)` — пауза приёма намерения (на время commit-действия / такла); во
    время паузы скорость плавно гаснет до 0.
- **Кто кормит намерение** (логика «куда бежать» остаётся в тех же файлах — меняется только
  *применение*):
  - **Человек:** `match_manager` считает camera-relative `dir` (как сейчас,
    [`match_manager.gd:528-539`](../../../scripts/match/match_manager.gd)) → `motor.set_move_intent(dir, sprint_scale)`.
    Вся текущая `move_toward`-по-позиции логика удаляется.
  - **ИИ:** `simple_ai` / `teammate_ai` уже считают `dir` → зовут `motor.set_move_intent(dir)` вместо
    записи позиции.

Побочная выгода: чинится хак из CLAUDE.md, где `PlayerVisual` и дриблинг меряют скорость по дельте
позиции — теперь есть настоящая `velocity`.

**Почему компонент, а не инлайн:** `match_manager` уже ~820 строк («один мозг»); физику движения
троих игроков туда тащить — раздувать. Компонент изолирован, тестируется отдельно, ложится на уже
принятый в проекте раздел gameplay/presentation.

## Модель движения

Framerate-независимая версия рецепта OpenSoccer (у них модель на фикс. 60 fps через покадровое
`velocity *= 0.94`; делаем корректно через `delta`). В `_physics_process`:

```gdscript
# desired = intent_dir * top_speed * speed_scale   (или Vector3.ZERO, если ввода нет / control_locked)
var rate := ACCEL if desired.length() > 0.1 else DECEL
velocity = velocity.move_toward(desired, rate * delta)
velocity.y = 0.0
set_velocity(velocity)
move_and_slide()
```

**Тюнинг-константы** (в `FootballConstants`, чтобы не плодить инлайн-литералы — известная боль
проекта; инлайновый `8.0` из `match_manager` удаляется):

| Константа | Значение (старт) | Смысл |
|---|---|---|
| `LOCO_TOP_SPEED` | `8.0` | обычная максимальная (сохраняем текущую) |
| `LOCO_SPRINT_SPEED` | `11.0` | максимальная при спринте |
| `LOCO_ACCEL` | `30.0` м/с² | полный разгон за ~0.27 с |
| `LOCO_DECEL` | `20.0` м/с² | торможение мягче разгона → лёгкий глайд («вес») |
| `LOCO_TURN_RATE` | `12.0` /с | скорость доворота тела к направлению движения |
| `LOCO_TURN_MIN_SPEED` | `1.5` м/с | ниже — не доворачиваемся (не крутимся на месте) |
| `LOCO_MAX_BANK_DEG` | ~`12°` | максимальный крен корпуса в повороте |
| `LOCO_RUN_REF_SPEED` | тюнится приёмкой | скорость, при которой клип `run` выглядит естественно (для анти-слайда) |
| `LOCO_SPRINT_REF_SPEED` | тюнится приёмкой | то же для клипа `sprint` |

Числа — стартовые, финальные подбираются живой приёмкой.

## Разворот и banking

- **Разворот тела** сглаживаем к направлению `velocity` через `lerp_angle` с темпом `LOCO_TURN_RATE`,
  только при скорости > `LOCO_TURN_MIN_SPEED` (иначе на месте не крутимся, держим последнее
  направление). Тело `CharacterBody3D` **остаётся строго вертикальным** — на нём коллайдер.
- **Banking наклоняем у `PlayerVisual` (узел `Model`), не у тела** — чисто ложится на раздел
  gameplay/presentation. Motor считает боковую компоненту ускорения → передаёт визуалу величину крена
  → тот кренит `Model` по roll, масштабируя по скорости (медленно — крена нет). Новый маленький шов в
  API визуала: `set_lean(amount: float)`.

## Анимация и анти-слайд

- `PlayerMotor` каждый кадр зовёт уже существующий `PlayerVisual.set_locomotion(velocity)` — визуал
  берёт **длину настоящей скорости** для выбора стейта и скорости клипа, вместо самозамера по дельте
  позиции (убираем хак; `_explicit_speed` становится основным путём).
- Локомоцию `PlayerVisual` перестраиваем с `BlendSpace1D(idle, run)` на структуру **idle / run /
  sprint** со скоростью клипа, привязанной к реальной: `TimeScale = actual_speed / ref_speed`
  (`LOCO_RUN_REF_SPEED` / `LOCO_SPRINT_REF_SPEED`) — ровно приём OpenSoccer (`RunSpeed/scale`).
  Переходы между стейтами по порогам скорости с коротким xfade.
- Фолбэк-капсула и всё поведение при отсутствии клипов сохраняются.

## Спринт (входит в этот спек)

Складываем сюда, потому что структуру анимации локомоции мы всё равно перестраиваем — добавлять
спринт потом значило бы трогать тот же код дважды.

- **Ввод:** новое действие `sprint`, **hold** (не toggle) — держишь → целевая скорость
  `LOCO_SPRINT_SPEED`, отпустил → обратно. Регистрируется в `_setup_inputs()` (**не** в
  `project.godot` — по конвенции проекта). Клавиша Shift + кнопка геймпада.
- **Модель:** `match_manager` при зажатом Shift передаёт `speed_scale = LOCO_SPRINT_SPEED /
  LOCO_TOP_SPEED` в `set_move_intent`.
- **Анимация:** стейт `sprint` (клип `sprint`). Ассет автор дотащит через пайплайн Mixamo→glb.
- **Фолбэк:** нет клипа `sprint` → спринт играется как `run` с повышенным `TimeScale`. Приемлемо, не
  блокирует разработку.
- **Без стамины** — отдельная геймплейная механика, не про фил; задел `speed_scale` остаётся.
- **ИИ спринт не даём** — ограничиваем объём; человек только.

## Взаимодействия

- **Дриблинг:** `ball_controller` теперь читает настоящую `velocity` носителя (сейчас — суррогат по
  позиции). Связку проверить при реализации: velocity-matching дриблинга должен стать точнее, не хуже.
- **Commit-действия (пас/удар):** на старте `motor.set_control_locked(true)`; по сигналу
  `PlayerVisual.action_finished` — снять. На время блокировки скорость плавно гаснет до 0 (естественная
  постановка ноги). Вешаем на уже существующие `_action_player` и сигналы визуала.
- **Слайд-такл:** оставляем как есть (`move_and_collide`) — motor на время такла уступает (пауза через
  `set_control_locked`). Территория спека №2; здесь только гарантируем, что новая модель с ним не
  конфликтует.
- **Камера:** не трогаем (следит за Z мяча).

## Открытый вопрос: коллизии игроков

Сейчас игроки движутся позицией и **проходят сквозь друг друга**. С `move_and_slide()` они начнут
сталкиваться — реалистичнее, но меняет фил и может влиять на такл/дриблинг (толкотня у мяча).

**Рекомендация:** дать полевым игрокам мягкое столкновение — либо тонкие капсульные коллайдеры без
жёсткого расталкивания, либо слои коллизий так, что игроки не «пробивают» друг друга, но и не
залипают. Финально решаем живой приёмкой; в план заложить как явный шаг тюнинга с фолбэком «если
толкотня ломает геймплей — временно отключить взаимные коллизии полевых, оставив только границы поля».

## Тестирование

- **Headless-проверка** математики motor по шаблону `tests/*.gd` (`extends SceneTree`, печатает
  `CHECK PASS`/`CHECK FAIL`, exit 0/1). Чистые/детерминированные свойства:
  - из покоя за время `t` при полном намерении скорость достигает ~`top_speed` (в пределах `ACCEL`);
  - при снятии намерения скорость монотонно падает до 0 темпом `DECEL`;
  - доворот не срабатывает ниже `LOCO_TURN_MIN_SPEED`.
- **Фил, banking, анти-слайд, коллизии** — только живым прогоном игры (headless анимацию/рендер не
  видит; это прямо оговорено в CLAUDE.md).

## Риски

- **Две модели ИИ + человек на новой модели одновременно** — регресс поведения ИИ (застревание на
  коллизиях, дрожание у цели). Митигируется общим компонентом (один код на всех) и тюнингом
  `DECEL`/порога у цели.
- **Коллизии игроков** (см. открытый вопрос) — главный источник неожиданного поведения.
- **Связка дриблинга** — velocity-matching завязан на скорость носителя; смена источника скорости
  может потребовать перетюнить коррекцию в `ball_controller`.

## Вне рамок (сознательно)

- **Foot IK** (`IKModifier3D`/`ChainIK3D`) — поле плоское, маржинальная польза; полировка «когда-нибудь».
- **Ragdoll / physics-blending** — **спек №2, сразу после этого** (импульсный ragdoll на подкате;
  пре-реквизит — причесать tackle-код: убрать `[TACKLE_DEBUG]`, вернуть детект фола).
- **Motion matching** — избыточен для планки «не выглядеть дёшево».
- **Стамина, walk-клип, спринт для ИИ, анимации разворота на месте** — задел есть, реализация позже.
