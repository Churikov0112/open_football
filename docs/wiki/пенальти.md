# Пенальти (Фаза A — `penalty_controller.gd` + `penalty_logic.gd`)

Общий контур стандартов, intent-шов и гейтинг менеджера — см. [[стандарты-и-intent-seam]].

## Что это

Клавиша **P** (`penalty_debug`) стажит пенальти в атакуемые ворота. Фикс 3-е лицо за точкой; **жёлтое
мировое кольцо** на плоскости ворот — реткл (стик/стрелки двигают, hold `kick` заряжает силу — кольцо
растёт с разбросом); **плавно возвращается в центр без стика** (`PEN_RETICLE_RETURN`). Отпуск бьёт, или
**`combo_modifier`+kick** (Q+D / LB+X) — черпачок. **Прямой** летит в `aim + равномерный сэмпл в диске
разброса` (больше сила → больше диск → выше промах). Для **черпачка сила = дальность приземления**
(мало → перед линией, в меру → в ворота, полная → через перекладину). Только прямой + чип (curl в
Фазе A нет).

## Alt+K — пенальти В НАШИ ворота, человек играет нашего вратаря

`keeper_dive_debug` (Alt+K): стажит пенальти в team_1 (Home) ворота на `+field_length` (наш вратарь
защищает), бьёт **team_2 (красный) полевой** (`_away_outfielder()`, `AIKickerIntent`), человек рулит
**нашим вратарём** (`SetPiecePresentation.Role.KEEPER` → пенальти-камера + cyan keeper-маркер, без
реткла/power-bar; человек выбирает зону нырка через `HumanKeeperIntent`). `controlled_player` **не**
трогается. `HumanKeeperIntent` cfg несёт **`lat_sign` (= `_into` ворот, −1 для +Z)** — камера пенальти
всегда за точкой смотрит на ворота, значит экран-право = мировой X знака `_into`; без флипа вратарь
нырял бы в зеркальную сторону (был реальный баг на +Z-воротах). `_clear_box()` держит **обоих** вратарей
(`role_gk`) в воротах.

## Разделение gameplay/математики

`PenaltyController` (`extends Node`) гоняет `SETUP→AIM→STRIKE→WATCH`; **вся геометрия — чистые статические
функции в `PenaltyLogic`** (`class_name PenaltyLogic extends Object`, **не читает FootballConstants**,
тест `check_penalty_logic.gd`): `move_reticle`, `spread_radius`, `power_speed`, `sample_in_disc`
(равномерно через `sqrt(u)`), `plane_point_to_world`, `random_dive_zone`, `zone_target`,
`enum Zone {LOW_L,HIGH_L,LOW_R,HIGH_R,CENTER}`. Векторы запуска — `ShotSystem.ballistic_to` (прямой) /
`PassSystem.launch_lob` (чип — горизонталь **drag-компенсирована** через `KeeperLogic.drag_horizontal_
speed`, чистая баллистика недолетает под драгом). RNG через seedable `_pen_rng`.

## Контроллер гоняет ОДНО пенальти

Эмитит `struck` на контакте, `release_after_strike` (по умолч. `true` — одиночное). На `action_contact`
бьющего запускает мяч, зовёт `keeper.begin_penalty_dive(zone, _pending_launch)` (передаёт launch-вектор —
скорость мяча ещё 0 этот кадр), **запускает мяч в игру** и переходит в фазу `WATCH` — держит
пенальти-камеру/управление `PEN_WATCH_TIME` (1.5с), затем `_release()` возвращает к обычной игре.
Гол/сейв/промах разрешают существующие системы (`GoalArea`→`_confirm_goal` Law-10, см. [[сетка-ворот]]),
НЕ контроллер: `WATCH` — только пост-ударное удержание кадра, **классификации исхода** намеренно нет —
серия (несколько попыток) — будущий слой (`release_after_strike=false`).

## Цепкий нырок (as-built)

`begin_penalty_dive(zone, launch_vel)` берёт launch-вектор и, когда угаданная **сторона** совпала с
реальной траекторией, ныряет в **реальную drag-aware точку пересечения** (`KeeperLogic.shot_intercept`
на `launch_vel`) вместо фикс-точки зоны, и **пропускает `KEEPER_SAVE_ERROR`** (`no_error=true`) — так
**верная сторона надёжно достаёт даже угловой удар**, а **неверная всё равно мажет**. Угадать сторону
всё ещё нужно. `CENTER` держит вратаря центральным, высоту разрешает обычный рефлекс
(`_should_catch_high` + `_catch_clip_for_height`, или `miss_top` выше certain-полосы). См. [[вратарь]].

## Keeper penalty sub-mode

`set_penalty_mode(true)` на SETUP **жёстко сбрасывает вратаря из ЛЮБОГО состояния** (выход из
нырка/one-shot, релиз мяча, снап в центр линии, сброс флагов) — P могут нажать посреди нырка/раздачи —
затем держит центр в `keeper_idle`, реактивный боковой сейв OFF (гадать вслепую), но **центральный
рефлекс ON**. Приставные шаги по линии до разбега — `_penalty_hold` (`KEEPER_PEN_STEP_*`). `_penalty_hold`
авто-снимает режим на ловле/за линией/полёте прочь.

## Root-motion разбег (A1)

`penalty_kick_l`/`penalty_kick_r` — единственные клипы с реальным ~3м разбегом, **НЕ** в `IN_PLACE_CLIPS`
(root-трансляция сохранена). `PlayerVisual` включает `root_motion_track` на Hips, `consume_root_motion()`
даёт покадровый ход в **игровых метрах** (сырой — в немасштабированных Hips-единицах, ×`PEN_ROOT_SCALE`,
калибровка `tools/measure_penalty_runup.gd`). Контроллер пред-ставит бьющего на `PEN_RUNUP_DIST` назад и
применяет ход каждый strike-кадр (мотор locked). **Переэкспортил клипы — перезапусти
`measure_penalty_runup.gd` и обнови `PEN_ROOT_SCALE`/`PEN_RUNUP_DIST`.**

**Две root-motion гочи (обе кусали):** (1) `root_motion_track` ставится **только для пенальти-клипа
внутри `trigger()`**, НЕ глобально в `_build_anim_tree` — глобальный трек извлёк бы Hips из **всех**
клипов (`keeper_idle` парит, нырки теряют вертикаль). (2) Трек чистится **после завершения кроссфейда
возврата** (`get_fading_from_node() == StringName()`), НЕ на `lock` — чистка посреди фейда переприменяет
переднюю Hips-позу и тело **скользит назад** в idle.

Константы — секция PENALTY в [[константы]]. Тесты: `check_penalty_logic.gd`, `check_penalty_flow.gd`,
`check_penalty_keeper_line.gd`. Инструмент калибровки — `tools/measure_penalty_runup.gd`. Чувство
(прицел, кадрирование, разбег, разнообразие нырков) — только человеком. Спека:
`docs/superpowers/specs/2026-07-15-penalty-design.md`.
