# Дизайн: удары по воротам, вынос, голова и планирование действий

**Дата:** 2026-07-10
**Статус:** согласован, готов к плану реализации
**Связано:** [pass-system-design](2026-07-10-pass-system-design.md), [living-locomotion-design](2026-07-09-living-locomotion-design.md), [3d-assets-pipeline-design](2026-07-08-3d-assets-pipeline-design.md)

## 1. Цель и охват

Добавить полноценную систему завершения атаки: три типа ударов ногой, контекстный вынос,
удар и пас головой, а также планирование действия игроком, который ещё не владеет мячом.
Одновременно — переход модели мяча на схему **OpenSoccer** (мяч всегда физически
сталкивается с игроками, дриблинг импульсно-«трапный»), потому что удары/блоки/сейвы
опираются на неё.

Фича оформлена одним спеком, реализуется **фазами** (план `writing-plans` разобьёт на задачи):

- **Фаза 0** — миграция модели мяча (фундамент).
- **Фаза 1** — три удара ногой + прицел/промахи + Magnus (кручёный) + вынос.
- **Фаза 2** — планирование/очередь действия для игрока без мяча (все удары и все пасы).
- **Фаза 3** — голова (удар и пас головой, авто-подбегание, решение «нога/голова/недосягаемо»).

Порядок Фаз 2→3 намеренный: очередь проще тестировать на ударах ногой, а голова навешивается
сверху на готовый механизм прогноза/подбегания.

### Вне охвата (YAGNI сейчас)

- Вратарь — только хук `SaveArea` на мяче, без реализации сейва.
- Единоборства/удар головой в прыжке через соперника.
- Отдельные анимационные клипы удара ногой (кручёный/черпачок/вынос/удар) — переиспользуем
  клип `pass`, как сейчас (см. `PlayerVisual.ACTION_CLIPS`).
- Новые типы ударов у ИИ-соперника — его текущий удар оставляем как есть.
- Фол за жёсткий блок.

## 2. Архитектура и модули

Зеркалим удачный паттерн пас-системы (чистые статик-функции + commit-action + константы-параметры).

- **`scripts/match/shot_system.gd`** (`class_name ShotSystem extends Object`) — чистые статик-функции,
  **не читают `FootballConstants`** (тюнинг передаётся параметрами), headless-тестируемы:
  - `goal_aim_point(...)` — точка в створе: авто-цель + смещение по facing/стику к углу + разброс,
	растущий с дистанцией и зарядом. Заглушка под будущего вратаря (не всегда центр).
  - `bullet_velocity(...)` — плоско-настильная скорость к точке прицела, подъём по заряду.
  - `curl_launch(...)` — стартовая скорость к углу + вектор `curl` (Magnus).
  - `chip_velocity(...)` — баллистика черпачка (как `PassSystem.launch_lob`).
  - `clearance_velocity(...)` — мощный вынос по facing/стику вдаль, лёгкий подъём.
  - `predict_ball_pos(pos, vel, t, gravity, drag)` — баллистический прогноз позиции мяча (общий
	для головы и очереди).
  - `head_decision(...)` — по прогнозной высоте: `HEADER / FOOT / UNREACHABLE`.
- **`scripts/ball/ball_controller.gd`** — стейт-машина мяча, импульсный трап, Magnus в
  `_integrate_forces`, всегда-столкновение, `launch_curl()`, блок/сейв-хук. Velocity-matching удаляется.
- **`scripts/match/match_manager.gd`** — расширение `ChargeAction`, диспатч ударов, контекст
  «удар vs вынос», очередь планирования, авто-подбегание под голову, реакции блока.
- **`scripts/player/player_visual.gd`** — `ACTION_TIMING` для головы (клипы `idle_header`/
  `idle_header_jump` уже заведены).
- **`scripts/data/football_constants.gd`** — новая секция `SHOOTING`.
- **Тесты:** `tests/check_shot_system_math.gd`.

## 3. Фаза 0 — миграция модели мяча (OpenSoccer)

**Причина «пакета»:** «мяч всегда сталкивается» несовместимо с velocity-matching — жёсткое
присваивание `linear_velocity` каждый тик дралось бы с физическим контактом капсулы дриблёра
(джиттер, ср. хотфикс `78990c8`). Поэтому включение столкновения = обязательный переход дриблинга
на импульсно-трапную модель. Одно без другого не работает.

### Стейт-машина мяча

`enum BallState { OPEN, TRAPPED, FLIGHT, CAUGHT }`. Поле `dribbler` и весь velocity-matching в
`_integrate_forces` **удаляются**. Поле `_curl: Vector3` ненулевое только у кручёного; Magnus
применяется, пока `state == FLIGHT and _curl != 0` (боковой + подъёмный импульс с затуханием, как
в референсе OpenSoccer: `(curl.z*left + curl.y*UP) * delta * k`, `curl *= decay`).

### Столкновение — всегда включено

- Мяч остаётся на слое 1; в `collision_mask` добавляем слой игроков (`PLAYER_COLLISION_MASK`) и
  `BOUNDARY_COLLISION_LAYER`.
- **Асимметрично:** маску игроков (`CharacterBody3D`) не трогаем — игрок ходит свободно, а мяч
  (`RigidBody`) отскакивает от капсул (движок разрешает контакт, т.к. мяч видит игрока в своей
  маске; кинематический игрок не сдвигается).
- `continuous_cd = true` (защита от туннелирования быстрых ударов сквозь игрока/штангу),
  `contact_monitor` включён (уже используется `body_entered`), тюнинг `physics_material`
  (friction/bounce/damp под качение).
- `TackleArea`/`GoalArea` (`body == ball`) продолжают работать — мяч на слое 1.

### Дриблинг — импульсный трап

- У каждого полевого игрока — дочерний `TrapArea` (`Area3D`) впереди. Медленный `OPEN`-мяч,
  попавший в зону разрешённого владельца (с учётом кулдаунов последнего кикнувшего) →
  `ball.trap(player)`: `state = TRAPPED`, владелец = этот игрок.
- Пока `TRAPPED`, владелец каждый физкадр зовёт `ball.dribble(dir, speed)`; в `_integrate_forces`
  мячу гасится скорость и придаётся импульс вперёд по facing/движению (масштаб от скорости) +
  лёгкий `UP`, удерживая мяч ~0.5 м перед игроком.
- Отпускание владения: `kick()` / `launch()` / `launch_curl()` или отбор/блок.

### Владение переопределяется на `ball.state`/`ball.player`

Всё, что сейчас читает `ball.dribbler` (авто-переключение управляемого игрока, `_we_possess()`,
приёмка паса), перевешиваем на нового владельца. `get_dribble_direction()` /
`peek_dribble_direction()` остаются (facing владельца) для прицела.

### Блок/сейв (хук)

Существующий `body_entered` (`_on_ball_collision`) расширяем: `state == FLIGHT` и `body` — игрок →
блок: гасим скорость, `_curl = 0`, `state = OPEN`, метим `lastPlayer` (дальше обычная борьба за
подбор; мгновенной передачи владения нет). Вратарский `SaveArea` — задел на будущее, не реализуем.

### Риск-лист Фазы 0 (ручная приёмка)

- Ощущение дриблинга (главный тюнинг-проход — импульсный трап менее «прилипчив», чем
  velocity-matching).
- Разлёт мяча/капсулы на спавне; трапнутый мяч не должна сбивать собственная капсула владельца.
- Примирение «честного перехвата» пасов (`PassSystem.interception_time`) с новым **физическим**
  перехватом — ИИ-реакцию «побежать к мячу» оставляем, сам отбор отдаём физике.

## 4. Фаза 1 — три удара ногой + вынос

### Ввод/комбинации (правим только `_setup_inputs()`, не `project.godot`)

| Действие | Клавиатура | Геймпад | ChargeAction |
|---|---|---|---|
| Прямой удар / вынос | `D` (держать — заряд) | `X` | `SHOT` (контекст: удар или вынос) |
| Кручёный | `E`+`D` | `RB`+`X` | `SHOT_CURL` |
| Черпачок (chip) | `Q`+`D` | `LB`+`X` | `SHOT_CHIP` |

`E`/`RB` — новый combo-модификатор (сейчас его нет; `Q`/`LB` уже занят под пас-комбо/свап).
Держится вместе с `D`/`X`. Заряд — существующая charge-механика (`_start_charge`/`_fire_charge`),
удар доигрывается через commit-action по сигналу `action_contact`.

### Прицел и промахи (гибрид, `ShotSystem.goal_aim_point`)

- Определяем ворота соперника. Если игрок в атакующей зоне и в целом повёрнут к ним → **удар**:
  базовая точка — центр створа, смещённая facing/стиком к ближнему углу (лево/право), плюс
  вертикаль по заряду (сильнее заряд → выше цель → выше риск через перекладину). Затем угловой
  **разброс** `apply_scatter` (растёт с дистанцией и зарядом — на максимуме «велик риск промаха»).
  Точка в створе — заглушка под будущего вратаря (не всегда центр).
- Если игрок далеко от чужих ворот или повёрнут в свою сторону → **вынос**: мощно по facing/стику
  вдаль (без прицела в створ), лёгкий подъём. Порог — зона/дистанция до чужих ворот
  (`CLEARANCE_ZONE_*`).

### Три траектории

- **Прямой (bullet)** — `ShotSystem.bullet_velocity`: плоско-настильно к точке прицела, `y`-подъём
  растёт с зарядом. `_curl = 0`. Отскоки/качение — штатная физика.
- **Кручёный (curl)** — `ShotSystem.curl_launch`: стартовая скорость к ближнему углу + вектор
  `_curl` (боковой — знак от того, к какому углу ближе facing; подъёмный — для дуги). Заряд
  усиливает высоту, дальность **и** кривизну. `ball.launch_curl(vel, curl)` → `state = FLIGHT`,
  Magnus каждый кадр с затуханием.
- **Черпачок (chip)** — `ShotSystem.chip_velocity`: та же баллистика, что у лоба
  (`PassSystem.launch_lob`), заряд задаёт высоту параболы. `_curl = 0`.

Все три и вынос идут через `ball.launch()`/`launch_curl()` (импульс по `action_contact`), физически
сталкиваются с игроками в полёте → возможен блок/рикошет.

## 5. Фаза 2 — планирование/очередь действия

### Когда активна

Управляемый игрок **не владеет** мячом (`ball.player != controlled_player`), но мяч летит/катится
к нему (типично — после паса ввод уже переключился на принимающего, работает receive-assist).
Нажатие кнопки удара/паса (с любым combo) не бьёт сразу, а **ставит действие в очередь** и
запускает заряд.

### Механика заряда («удержание копит»)

- Держишь → шкала растёт как обычно.
- Отпустил до касания мяча → фиксируем `ratio` в очереди.
- Всё ещё держишь в момент касания → бьём на текущем `ratio` (автофайр на максимуме).

### Сила в одно касание = заряд + скорость влетающего мяча

Эффективная сила в момент касания:
`effective = base(ratio) + QUEUE_BALL_SPEED_GAIN * incoming_speed` (клампится до максимума).
Быстрый пас/прострел можно замкнуть мощным ударом даже при коротком удержании; «мёртвый»
медленный мяч требует полноценного заряда. `incoming_speed` = модуль `ball.linear_velocity` на
момент касания. Правило действует **только для очереди в одно касание** — при обычном владении мяч
у ног медленный, вклад ≈ 0.

### Поля и срабатывание

Поля (`match_manager`): `_queued_action: ChargeAction`, `_queue_player`, `_queue_ratio`,
`_queue_combo`, `_queue_timer`. В момент, когда `_queue_player` дотягивается до мяча (там, где
обычно был бы `ball.trap()`), вместо `TRAPPED` сразу диспатчим отложенное действие — удар/пас «в
одно касание». **Прицел/цель считаются в момент касания, а не постановки в очередь** (по актуальным
facing/стику и позициям), чтобы решение не устаревало.

### Область

Все три удара (`SHOT`/`SHOT_CURL`/`SHOT_CHIP`, включая контекстный вынос) **и все пять пасов**
(короткий, на ход, лоб, стенка, на ход верхом). Очередь хранит `ChargeAction`+combo и
переиспользует те же пути `_fire_charge`/`_fire_pass`.

### Отмена (каждый физкадр, `_clear_queue()`)

Мяч перехватил/трапнул кто-то другой, ушёл в аут, `_queue_timer` истёк, сменился управляемый игрок,
или `_queue_player` сбит с ног → очередь чистится, маркеры прячутся.

### Авто-подбегание под мяч (для любого действия ногой)

Пока действие в очереди, игрок автоматически бежит в прогнозную точку встречи с мячом (в ноги),
перекрывая ручной ввод движения на время подстройки — это **общий** механизм, а не только для
головы. Переиспользуем receive-assist (подведение к прогнозной позиции мяча). Голова (Фаза 3)
надстраивает над этим же механизмом лишь вариант «целиться под голову» вместо «в ноги». Не
добежал/перехватили → сброс очереди.

### UI / связь с receive-assist

`power_bar` виден во время зарядки и вне владения; жёлтый маркер цели показываем и для
запланированного паса. Receive-assist (подведение принимающего к прогнозной точке мяча), очередь и
авто-подбегание работают вместе.

## 6. Фаза 3 — голова

### Решение «нога / голова / недосягаемо» (`ShotSystem.head_decision` + `predict_ball_pos`)

Когда игрок инициирует удар/пас (сразу или из очереди), а мяч ещё не у ног, прогнозируем траекторию
(баллистика + драг) и берём высоту в точке/окне встречи с игроком:

- На уровне головы или выше, но в досягаемости (`HEAD_HEIGHT ± HEAD_REACH_BAND`) → **голова**.
- Сильно выше `HEAD_HEIGHT + HEAD_REACH_BAND` (не допрыгнуть) → **ничего** (действие не
  ставится / сбрасывается).
- Ниже уровня головы → **удар/пас ногой** (combo имеет значение — тип из Фаз 1/2).

### Авто-подбегание под голову

Тот же общий механизм авто-подбегания из Фазы 2, но при решении «голова» цель встречи — прогнозная
точка на уровне головы (`HEAD_HEIGHT`), а не в ноги. Для удара/паса ногой подбегание уже работает
из Фазы 2 (в ноги). Не добежал/перехватили → сброс.

### Удар головой

**Всегда в створ ворот соперника — независимо от facing игрока И направления стика.** Стик прицел
удара головой не трогает (в отличие от ножного удара, где он подкручивал выбор угла): направление =
авто-цель в раму (`goal_aim_point` с `side_bias = 0` / небольшим авто-выбором ближнего угла) +
`goal_assist` (магнит) + разброс. Импульс — в момент `header`-контакта. Клипам `idle_header`/
`idle_header_jump` добавим `ACTION_TIMING` (`contact`/`lock`). Combo при голове роли не играет
(кручёный/черпачок головой не делаем) — любой вариант = удар головой к воротам.

### Пас головой (скидка)

**Направление задаётся строго стиком** (в отличие от удара головой): скидка в сторону стика
(ближайший партнёр по направлению — `PassSystem.select_target`, либо просто по вектору стика).
Импульс — короткий низово-верховой в сторону скидки. Без стика — фолбэк по facing.

### Тип действия решает кнопка, не контекст

У головы нет «удар vs вынос»-контекста как у ноги. Кнопка **удара** (`D`/`X`) при верховом мяче →
**удар головой в ворота** (авто-цель). Кнопка **паса** (короткий/на ход) → **скидка головой по
стику**. Combo-модификаторы (кручёный/черпачок/стенка/верхом) на голове игнорируются — есть только
эти два исхода.

### Триггер

Голова возникает и при прямом действии (мяч на подлёте выше пояса), и из очереди: решение
принимается в момент, когда пора касаться мяча, по актуальному прогнозу.

## 7. Константы (`football_constants.gd`, секция `SHOOTING`)

Стартовые значения тюнятся живьём. Ориентировочный набор:

- **Прямой удар:** min/max сила, подъём по заряду.
- **Разброс:** база, рост с дистанцией, рост с зарядом.
- **Кручёный:** боковая и подъёмная сила `curl`, затухание Magnus.
- **Черпачок:** высота параболы по заряду.
- **Вынос:** `CLEARANCE_ZONE_*` (зона/дистанция до чужих ворот), сила/подъём.
- **Очередь:** `QUEUE_BALL_SPEED_GAIN` + клампы, окно `_queue_timer`.
- **Голова:** `HEAD_HEIGHT`, `HEAD_REACH_BAND`, окно прогноза траектории.
- **Мяч (Фаза 0):** friction/bounce/linear_damp/angular_damp, `continuous_cd`.

## 8. Тестирование

- **`tests/check_shot_system_math.gd`** (паттерн `check_pass_system_math.gd`) — чистые функции
  `ShotSystem`: `goal_aim_point` (смещение/клампы в створе), `bullet_velocity`, `curl_launch`
  (знак/величина curl), `chip_velocity`, `clearance_velocity`, `predict_ball_pos` (баллистика),
  `head_decision` (пороги высоты). RNG разброса — через переданный `RandomNumberGenerator` (seed),
  как в пас-системе.
- **Headless-регресс:** обе команды из CLAUDE.md (парсинг + баселайн ошибок сцены матча).
- **Ручная приёмка (обязательна):** Magnus/трап/блок/ощущение дриблинга, авто-подбегание под
  голову, сила удара с лёта, промахи — headless не ловит.

## 9. Порядок реализации

Фаза 0 приземляется и стабилизируется (ручная приёмка дриблинга) **до** Фазы 1, потому что
удары/блоки/сейвы опираются на всегда-столкновение и стейт-машину мяча. Далее 1 → 2 → 3.
