# 16 — Блок «вратарь-держатель не выходит из штрафной» в порте отсутствует

Status: ready-for-agent
Type: bug

Найдено разведкой фазы 6 (2026-08-05) попутно, к офсетам отношения не имеет. В отличие от
`CalculateGeomOffsets` ([тикет 14](./14-geom-offsety-mertvy-v-originale.md)) этот блок в оригинале
**живой** — стоит в `Humanoid::Process`, исполняется каждый тик.

**Blocked by:** фаза 8 (матч-слой) — нужны стороны команд и роль игрока по формации.

## Что не перенесено

`humanoid.cpp:745-760`, между лерпом rotation-smuggle и заполнением apply-буфера:

```cpp
if (match->GetBallRetainer() == player &&
    CastPlayer()->GetFormationEntry().role == e_PlayerRole_GK &&
    (match->IsInSetPiece() == false && match->IsInPlay() == true)) {
  // четыре OffsetPosition, загоняющие вратаря с мячом в руках обратно в штрафную
}
```

Смысл: вратарь, держащий мяч в руках, подтягивается обратно в свою штрафную — по `y` к границам
±20.05, по `x` к коридору от `-pitchHalfW + 0.1` до `-pitchHalfW + 16.4`. Сдвиг clamp'ится ±0.5 м и
домножается на 0.3 (по `y` и по дальней границе `x`) либо 0.4 (по ближней границе `x`).

## Состояние порта

В `src/gpf/HumanoidBase.cs` тик идёт от `UpdateRotationSmuggleOffset()` сразу к заполнению
apply-буфера — блока нет. Констант `20.05` и `16.4` в `src/gpf/` нет вовсе.

Суррогат `_isBallRetainer` в `Humanoid.cs:79` уже есть (сеттеры `SetBallRetainerSelf`/
`SetMatchContext`), а `IsInPlay`/`IsInSetPiece` приходят тем же `SetMatchContext`. Не хватает:

- **роли по формации** (`GetFormationEntry().role == e_PlayerRole_GK`) — формаций в порте нет;
- **стороны команды** (`team->GetSide()`, множитель `-1`/`+1` в трёх из четырёх условий) — команд в
  порте нет;
- `OffsetPosition` — проверить, есть ли эквивалент, при переносе.

## Почему не чинилось по ходу

Правило фазы 6: расхождение не по теме фазы — тикет, а не правка. Плюс без команд и формаций блок
физически не собрать.

## Как проверить после переноса

Сценарий оракула с вратарём, держащим мяч в руках, вне стандарта. `walk_line` этот путь не трогает
(контролируемый — полевой, мяч дальше 16 м), поэтому регрессию текущего нулевого диффа перенос дать
не должен — но прогнать обязательно.

- [ ] Блок перенесён дословно, числа из оригинала как есть
- [ ] Роль по формации и сторона команды приходят из настоящих `Player`/`Team`, не из заглушек
- [ ] Дифф `walk_line` остался нулевым
- [ ] Поведение проверено сценарием с вратарём
