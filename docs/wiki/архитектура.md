# Архитектура

Точка входа в вику. OpenFootball — аркадный футбол на Godot 4.7 / GDScript, поле в масштабе FIFA,
Windows-only, пока небольшой прототип (человек + ИИ-тиммейт против двух ИИ-соперников + вратари),
ещё не 11-на-11. Презентация гибридная: поле/разметка/ворота/газон/мяч генерятся кодом, а игроки —
реальные риггованные Mixamo-модели (см. [[презентация-и-ассеты]]).

## Один «мозг» — `scripts/match/match_manager.gd`

`extends Node3D`, корень `match.tscn`. Этот ~1000-строчный файл владеет почти всем: настройка ввода,
слежение камеры, процедурная разметка/ворота/газон/границы, переключение управляемого игрока,
удар/пас (заряд + deferred-impulse), вся машина слайд-подката. **Когда сомневаешься — логика тут.**

**Вход:** `main_menu.tscn` (главная сцена) → кнопка Start грузит `match.tscn`. `match.tscn` — **не**
самостоятельная точка входа.

## Узлы прошиваются кодом, а не в сцене

В `_ready()` `match_manager` строит два узла-ростера `Team` и спавнит каждого игрока (человек,
тиммейт, соперник, вратарь) через `PlayerFactory.spawn(config, team)` (см. [[фабрика-игроков]]).
`.tscn` минимальны — где узел получает поведение, ищи в `_setup_*`-функциях менеджера и в
`PlayerFactory.spawn`. Каждый полевой игрок получает `PlayerVisual`-инстанс ребёнком (риг + тинт кита).

## Компонент-мозги ИИ (дети тела, не `set_script` на нём)

- `scripts/ai/simple_ai.gd` (`extends Brain`) — соперник (team_2, **красный**): гонит мяч к воротам,
  бьёт, просит подкаты.
- `scripts/ai/teammate_ai.gd` (`extends Brain`) — тиммейт **и** `PlayerHome`, когда тот не управляется
  человеком (team_1, **синий**): встаёт под пас / гонит мяч.
- `scripts/ai/keeper_ai.gd` (`extends Brain`) — вратарь (по одному на ворота; home-вратарь
  **управляем человеком**). См. [[вратарь]].
- База `scripts/ai/brain.gd` (`class_name Brain extends Node`): `_body := get_parent()` кэшируется в
  `_ready()`. Каждый мозг читает своё тело через `_body`, **никогда `self`** — иначе ссылается на
  `Brain`-`Node`, а не на тело. Движение — через `_drive(dir, scale)`/`_stop()` базового класса
  (→ `PlayerMotor.find_on(_body)`).

**`MatchManager._ai_of(body) -> Node`** — единственная индирекция менеджера к полям/методам ИИ
(`wants_to_tackle`, `target_node`, `mark_target`, `begin_receiving`, `begin_give_and_go`,
`controlled_player`, `speed`, …): возвращает `body.brain()` если есть, иначе само тело. Использовать
на каждом новом call-site — прямой `body.some_ai_field` минует компонент.

## Вратарь особо

`match_manager` достаёт вратарей через `_keeper_at(goal_line_z)` / `_team_home.keeper()` /
`_team_away.keeper()` — **нет** синглтона `_keeper`. Контроллеры стандартов резолвят вратаря в
`start()`. Тело используется для freeze/исключения/идентичности контакта (`n == keeper`), а его
API/состояние (`goal_line_z`, `on_ball_contact()`, `set_penalty_mode()`, `_state`) — через `k.brain()`
(объявляй явно: `var kb: Node = k.brain()`, `:=` не компилируется — статический тип тела
`CharacterBody3D` не знает `brain()`). См. [[вратарь]].

## Судья и оркестрация

`scripts/match/match_referee.gd` (+ чистая `referee_logic.gd`, `boundary_logic.gd`) — edge-detection
рестартов: жеребьёвка и кикофф на старте матча и после гола (`_dispatch_kickoff`), атрибуция гола по
тому, в какие ворота влетел мяч (`g.side`), не по last-touch. Пока диспетчеризуется только
[[начальный-удар]]; остальные стандарты запускаются дебаг-клавишами. Roadmap оркестрации —
`docs/superpowers/specs/2026-07-22-match-orchestration-roadmap-design.md`. См. [[стандарты-и-intent-seam]].

## Сквозные инварианты

- **Gameplay и presentation разделены.** `CharacterBody3D` + мозг/ввод + `CollisionShape3D` — это
  gameplay; `PlayerVisual` — presentation, ребёнком. Никогда не запекай анимацию/модель в
  gameplay-скрипты. См. [[презентация-и-ассеты]].
- **Чистая математика — отдельными классами, без autoload.** `PassSystem`, `NetSim`, `KeeperLogic`,
  `KeeperPlayLogic`, `PenaltyLogic`, `FreeKickLogic`, `CornerLogic`, `GoalKickLogic`, `ThrowInLogic`,
  `KickoffLogic`, `RefereeLogic`, `BoundaryLogic`, `PlayerMotor` (статические функции) —
  **никогда не читают `FootballConstants`**, тюнинг приходит параметрами → headless-тестируемы.
- **Движение — `velocity` + `move_and_slide()` через `PlayerMotor`**, не прямой сдвиг позиции.
  Единственное исключение — слайд-подкат (`move_and_collide`). См. [[локомоция]], [[подкат-и-падение]].
- **Владение и команды — через группы** `team_1`/`team_2` (+ `role_gk`/`role_def`/`role_mid`/`role_fwd`,
  временная `fallen`). Проверяй `_same_team()`/группы, не идентичность узла.

## Проверка (headless)

Тестов/линта/CI нет, кроме двух headless-команд и `tests/check_*.gd`. **Обе команды нужны, ловят
разное:**

```
& "<godot>" --path "<repo>" --headless --quit
& "<godot>" --path "<repo>" --headless --quit-after 2 res://scenes/match.tscn
```

Первая грузит `main_menu.tscn` и парсит все `class_name` + autoload, но **не** грузит `match.tscn`
(значит `match_manager`/`teammate_ai`/`simple_ai`/`keeper_ai` ею не парсятся). Вторая инстансит
`match.tscn` и реально их гоняет. У второй есть **известный baseline ошибок** (setup-order
`!is_inside_tree()`, дубль-регистрация `ACTION_CLIPS` kick/pass, `WorldEnvironment3D`) — диффай по
**категории/тексту**, не по счётчику (счётчики выросли со вторым вратарём и слегка гуляют между
запусками). Чувство игры (accel, поворот, банкинг, отскок, ловля) headless не ловит — нужен человек.
Список тестов см. в [[конвенции]] и на страницах подсистем.

С 2026-07-29 `<godot>` — это **.NET-редакция 4.7.1** (точный путь — в CLAUDE.md): проект несёт
C#-solution `OpenFootball.sln` под порт ядра GameplayFootball. Третья проверка — `dotnet build`
(headless-команды C# сами не пересобирают, только грузят готовую dll из `.godot/mono/temp/bin`).
Baseline обеих headless-команд на .NET-редакции сверен — категории те же.
