# Пас

Пять типов паса + удар делят один заряд. Заряд-как-таймер — в [[архитектура|match_manager.gd]],
резолвинг (`fire_shot`/`fire_pass`) — в `scripts/match/action_executor.gd` (`ActionExecutor`, Фаза 3a).
Математика — `scripts/match/pass_system.gd` (`class_name PassSystem extends Object`): **чистые
статические функции, `FootballConstants` не читают** (тюнинг параметрами), headless-тестируемы без
autoload. Тест математики — `check_pass_system_math.gd`.

## Управление

Пока управляемый игрок near/дриблит мяч (полный ремап — [[конвенции]]):

| Действие | Клавиша | Пад | Огонь |
|---|---|---|---|
| Удар | `D` (заряд/отпуск) | X | deferred-launch (`ball.launch()`/`launch_curl()`, **не** `ball.kick()`), см. [[удар]] |
| Короткий низом | `X` | A | `PASS_SHORT` |
| На ход (низом) | `W` | Y | `PASS_THROUGH` |
| Навес | `A` | B | `PASS_LOB` |
| Стенка | `Q`+`X` | LB+A | `PASS_WALL` |
| Верховой на ход | `Q`+`W` | LB+Y | `PASS_THROUGH_AIR` |
| Спринт | hold `Shift` | RT | больший `speed_scale` (человек) |
| Смена игрока | `Q` | LB | swap **только без владения** (`_we_possess()`); с мячом `Q`/`LB` — модификатор комбо |

`combo_modifier` (`Q`/`LB`) контекстный, проверяется каждый кадр: без владения → swap; удержан при
`pass_short`/`pass_through` → WALL/THROUGH_AIR-вариант. Пятой кнопки нет — модификатор удваивает три
кнопки в пять типов.

## Заряд

`enum ChargeAction { NONE, SHOT, SHOT_CURL, SHOT_CHIP, CLEARANCE, PASS_SHORT, PASS_THROUGH, PASS_LOB, PASS_WALL, PASS_THROUGH_AIR }`
(`SHOT_CURL`/`SHOT_CHIP` активно резолвятся в [[удар]], `CLEARANCE` — вынос).
Один `power_bar` на удар и все 5 пасов, полностью в `match_manager` (заряд-как-таймер специфичен вводу,
Фаза 3a вынесла лишь резолвинг): `_start_charge` / `_fire_charge` / `_cancel_charge`. Тайминг:
`KICK_CHARGE_MAX_TIME` (локальные 0.5с, только удар) vs `PASS_CHARGE_MAX_TIME` (0.6с). `_fire_charge()`
диспатчит в `ActionExecutor`: `SHOT` → `.fire_shot()`; иначе → `.fire_pass(action, player, ratio)`.
Эффект заряда разный: air-типы (`LOB`/`THROUGH_AIR`) лерпят высоту дуги; наземные (`SHORT`/`THROUGH`/
`WALL`) кормят `charge_ratio` прямо в `PassSystem.ground_pass_speed()` — скорость из дистанции/времени.

## `ActionExecutor` (deferred-impulse)

`fire_shot()`/`fire_pass()` ставят `_action_player`/`_action_power`/`_kick_action_active=true`, играют
анимацию и **ждут** `PlayerVisual.action_contact` перед запуском мяча: удар → `ball.launch()`/
`ball.launch_curl()` (`fire_shot` всегда ставит `_action_power = -1.0` сентинел, ветка launch — **не**
`ball.kick()`); пас → `ball.launch()`/`launch_lob` (различает тип по полям `PassParams`). Менеджер читает состояние через `action_player()` /
`is_kick_action_active()`. Callback-хелперы менеджера (`_aim_dir`, `_ai_of`, `_player_visual`, …)
объявляй с явным типом (`var x: PlayerVisual = _manager._player_visual(...)`), `:=` не компилируется
(`_manager` типа `Node`). Тест: `check_action_executor.gd`.

## `PassParams`

`scripts/match/pass_params.gd` (`class_name PassParams extends RefCounted`) — плоский холдер (не
фабрика-читатель констант, ради headless-теста): `power`, `peak_height`, `extra_lead`, `is_air`,
`is_wall` + `enum PassType`. Поведением рулят поля, не тег типа.

## Девять функций `PassSystem`

- `select_target(...)` — авто-аим: score = `dot(dir, aim) − dot_bias*(dist/max_range)`, aim =
  `ball.peek_dribble_direction()` (телеграф) / `get_dribble_direction()` (при выстреле). → индекс или −1.
- `lead_point(...)` — точка «на ход»: упреждение по скорости цели + `extra_lead`. Стоячая цель → сама
  позиция. `ball_speed` тут = `PASS_LEAD_SPEED_ESTIMATE` (реальная скорость ещё неизвестна).
- `receive_point(receiver_pos, ball_pos, ball_vel, lead_time, on_line_dot)` — точка доводки принимающего:
  ведёт по скорости мяча на `lead_time` вперёд, но при `|dot| > on_line_dot` (мяч летит почти в/от нас)
  встречает на линии без бокового упреждения. Питает receive-assist.
- `launch_ground(from, to, power)` — плоская скорость к `to` (обычно `power` = выход `ground_pass_speed`).
- `ground_pass_speed(dist, ratio, min_t, max_t, min_s, max_s)` — **пас всегда доходит, заряд лишь меняет
  скорость прихода:** `travel_time = lerp(max_t, min_t, ratio)`, `speed = clamp(dist/time, min_s, max_s)`.
- `launch_lob(from, to, peak, gravity)` — баллистическая дуга (`vy=sqrt(2gh)`), дистанционно-безопасна.
- `interception_time(...)` — детерминированная геометрия коридора (ширится с дистанцией), возвращает
  время перехвата или INF, без рандома и знания `AI_INTERCEPT_CHANCE`.
- `scatter_degrees(...)` / `apply_scatter(flat_dir, deg, rng)` — разброс (растёт с дистанцией, падает с
  assist); **всегда через явный `RandomNumberGenerator`** (`ActionExecutor._pass_rng`), не global `randf()`.

## `ball.peek_dribble_direction()`

**Read-only** близнец `get_dribble_direction()` (тот мутирует `_dribbler_prev_pos`, которое читает
`_integrate_forces` каждый тик). Телеграф-маркер зовёт аим каждый **render**-кадр при заряде — мутирующий
геттер гонял бы с физтиком и мяч визуально отставал бы. `peek_` использует только facing, безопасен
покадрово. При реальном выстреле — исходный мутирующий, там one-shot.

## Телеграф, приём, стенка, тиммейт

- **Телеграф-маркер** — второй жёлтый `MeshInstance3D` (`_target_indicator`) трекает текущий выбор
  `select_target` живьём каждый `_process()`-кадр, пока идёт заряд паса.
- **Receive-assist** — пока пас летит человеку-адресату (`_receive_active`/`_receiver`/`_receive_timer`
  на менеджере), `_handle_player_input()` **безусловно** ведёт ввод к предсказанной позиции мяча.
  Карве-аута «стик от мяча = намеренный забег» **нет** (после хэндоффа стик почти всегда нацелен на
  прошлого игрока). Фаза кончается на ловле/таймауте/потере/невалидности.
- **Give-and-go** — `PASS_WALL` ставит `is_wall`; на огне `begin_give_and_go()` (на `teammate_ai`)
  спринтит отдавшего в свободную зону на `PASS_WALL_WINDOW` — **единственное намеренное исключение
  «ИИ не спринтует»**. Возврат минует кулдаун через `_clear_wall_pass_cooldown()`.
- **`teammate_ai` роль приёма** (`enum Role { SUPPORT, RECEIVING, CHASING }`) — «выход на пас» для ИИ;
  **пока недостижима** в прототипе 1 человек + 1 ИИ (управление всегда уходит адресату) — сегодня
  «выход на пас» даёт человеческий receive-assist. Инфраструктура на будущее.
- **Честный перехват** — `_maybe_flag_interceptor()` гоняет `interception_time` против каждого team_2 в
  момент паса; если геометрически успевает — `_pass_rng.randf() > AI_INTERCEPT_CHANCE` решает, среагирует
  ли (шанс зевка), `begin_intercept()` бежит в точку после `AI_INTERCEPT_REACT`. Читает **реальную**
  скорость (`opp.get(&"speed")`), не `AI_SPEED` (легаси).
