# Приставные шаги вратаря на пенальти (позиционирование + заморозка) — дизайн

**Дата:** 2026-07-24
**Статус:** согласован, готов к плану реализации.
**Родитель:** `2026-07-24-keeper-penalty-dive-design.md` (KeeperIntent-шов, K-режим — уже реализован и работает). Это доработка K-режима.

## Что это

Сейчас в K-режиме (ИИ бьёт, человек — вратарь) вратарь стоит жёстко в центре линии всё время прицеливания, а зона нырка выбирается стиком на контакте. Добавляем **позиционирование телом до удара**: **стик меняет смысл по фазе**.

- **Фаза AIM (до разбега бьющего):** стик = движение тела приставными шагами вдоль линии ворот в сторону наклона (влево/вправо), нейтраль — стоит. Только X-координата на линии.
- **Момент начала разбега (AIM→STRIKE):** X-позиция тела на линии **фиксируется** (боковое движение стопорится).
- **Фаза STRIKE (разбег):** стик = направление прыжка — **ровно как сейчас** (читается на контакте `_on_kicker_contact`, `_struck_zone = dive_zone()`). Не меняется.
- **На контакте:** вратарь ныряет в зону, куда стик указывает в этот момент, **из замороженной точки** (она — origin нырка; сторона+высота — из `dive_zone()`).

Смысл — дать вратарю сыграть телом (сместиться, запутать), не выдавая заранее финального направления прыжка.

## Ключевые решения (из брейнсторма)

- **Высота (HIGH/LOW) — отдельного механизма не нужно.** Стоя на линии, вратарь позиционирует только X. Высота приходит в составе `dive_zone()` на контакте, как сейчас. Замороженная позиция = только origin нырка; полная зона (сторона+высота) — на контакте.
- **Момент коммита направления НЕ меняется** — остаётся на контакте (`_on_kicker_contact`, `_struck_zone = _keeper_intent.dive_zone()`). Меняется только: (а) добавляется AIM-позиционирование телом, (б) заморозка X на старте разбега.
- **ИИ-вратарь (P) не ездит — без гейта по типу.** Новый метод `KeeperIntent.step_lateral() -> float`: база `0.0`, `HumanKeeperIntent` → `stick.x`. Контроллер **всегда** шлёт `keeper.set_penalty_step(_keeper_intent.step_lateral())`; для ИИ это `0` → тело не смещается (центр, как сейчас). ИИ-раскачка (обманное движение) — **отложена**, добавится позже переопределением `step_lateral()` у `AIKeeperIntent`.

## Архитектура

### `KeeperIntent` / `HumanKeeperIntent`

```
# KeeperIntent (база) — добавить:
func step_lateral() -> float:   # желаемое боковое смещение по линии в AIM, [-1..1]; 0 = стоять
	return 0.0
```
`HumanKeeperIntent.step_lateral()` — читает `stick.x` через тот же переопределяемый `_axis` (боковая ось конфига `aim_lat`). `dive_zone()` не трогается.

### `keeper_ai.gd` — AIM-позиционирование + заморозка

Новые поля: `_penalty_step_lateral: float = 0.0` (последнее присланное контроллером), `_penalty_target_x: float = 0.0` (интегрированная цель X по линии), `_penalty_frozen: bool = false`.

Новые методы:
- `set_penalty_step(lateral: float)` — контроллер зовёт каждый AIM-кадр: `_penalty_step_lateral = lateral`.
- `freeze_penalty_position()` — контроллер зовёт на старте разбега: `_penalty_frozen = true`.

`_penalty_hold(delta, m)` — цель X теперь driven интегратором, а не фиксированным `X=0`:
- Пока не `_penalty_frozen`: `_penalty_target_x += _penalty_step_lateral * KEEPER_PEN_STEP_SPEED * delta`, кламп в `±(GOAL_WIDTH*0.5 - KEEPER_PEN_STEP_MARGIN)` (не за штангу). Заморожено → `_penalty_target_x` держится.
- Тело движется к `(_penalty_target_x, _ground_y, anchor_z)` тем же проп.-скорость-мотором, что сейчас (Z-якорь `goal_line_z + into*0.5` — без изменений). Локомоция уже `LOCO_STYLE_KEEPER` (стойка + приставные шаги) — новой анимации не нужно.
- Центральный рефлекс и авто-сброс режима — без изменений.

`set_penalty_mode(true)` — добавить сброс: `_penalty_step_lateral = 0.0`, `_penalty_target_x = 0.0`, `_penalty_frozen = false` (иначе следующий пенальти начнётся с замороженной/смещённой позиции прошлого).

### `penalty_controller.gd` — проводка

- **Во время AIM** (в `_aim_update`, guard `_keeper_brain.has_method(&"set_penalty_step")`): `_keeper_brain.set_penalty_step(_keeper_intent.step_lateral())` каждый кадр.
- **На старте разбега** (в `_fire()`, guard `has_method(&"freeze_penalty_position")`): `_keeper_brain.freeze_penalty_position()`.
- `_on_kicker_contact` — **не трогаем** (`_struck_zone = _keeper_intent.dive_zone()` остаётся). Нырок из `begin_penalty_dive(zone)` идёт из текущей (замороженной) позиции тела к `zone_target` — существующий `_begin_save` считает `to = target - _body.global_position`, т.е. origin = замороженная точка, само собой.

### Новые константы (`football_constants.gd`, KEEPER-секция)

- `KEEPER_PEN_STEP_SPEED` (напр. 3.0) — скорость бокового дрейфа по линии в AIM, м/с.
- `KEEPER_PEN_STEP_MARGIN` (напр. 0.5) — отступ от штанги, дальше которого не сместиться, м.

## Тестирование

Headless:
- **`check_keeper_intent.gd`** (расширить): `HumanKeeperIntent.step_lateral()` возвращает `stick.x` (через фейковый `_axis`); база `KeeperIntent.step_lateral()` == 0.0.
- **Валидация сцены** после проводки: `--quit-after 2 res://scenes/match.tscn`, дифф по baseline-категориям.
- Позиционирование/заморозка — физика/движение, headless не драйвит; проверяется вручную.

Фил (только человек за игрой):
- **K** — до разбега вратарь ездит приставными шагами вдоль линии по стику (влево/вправо/стоп), не заходя за штангу; в момент начала анимации разбега боковое движение стопорится; во время разбега стик выбирает направление прыжка; на контакте вратарь ныряет в выбранную зону из той точки, где замёрз. Прогнать: сместиться влево и нырнуть влево; сместиться влево, но нырнуть вправо (поздняя смена); остаться в центре.
- **P** (регрессия) — вратарь-ИИ стоит в центре до нырка, как было (`step_lateral()` базовый = 0).

## Границы (вне скоупа)

- **ИИ-раскачка** (вратарь-ИИ обманно двигается вбок, не выдавая своей зоны) — отложена; задел: переопределить `step_lateral()` у `AIKeeperIntent` независимой случайной раскачкой (не связанной с `_zone`).
- **Тюнинг физики нырка** (дотягивается ли до мяча) — прежний follow-up, не здесь.
- **Кросс-дайв при противоречивом вводе** (сместился вправо, нырнул влево → летит через все ворота) — допускается как следствие выбора человека, не спецом ограничивается.
