# Локомоция (`PlayerMotor`)

**Движение игрока — `velocity` + инерция через `move_and_slide()`, а не прямой сдвиг позиции.**
`scripts/player/player_motor.gd` (`class_name PlayerMotor`) — компонент-узел; `CharacterBody3D`
каждого полевого игрока получает его ребёнком, и он владеет 100 % физики движения этого тела.

Вызывающие (человек в [[архитектура|match_manager]], оба ИИ) **не трогают** `global_position`/`rotation`
для движения — они лишь зовут `motor.set_move_intent(dir, speed_scale)` раз в кадр. Мотор внутри:

- интегрирует скорость к желаемой (`LOCO_ACCEL` при разгоне, `LOCO_DECEL` при торможении —
  асимметрично, отпустил → глайд, а не мгновенный стоп);
- плавно доворачивает yaw тела к направлению скорости (`LOCO_TURN_ROT`, гейт ниже
  `LOCO_TURN_MIN_SPEED` — не крутится на месте);
- считает **сглаженный** крен из бокового ускорения (`smooth_scalar` при `LOCO_BANK_SMOOTH` — сырой
  скачет, WASD-ввод дискретный) → `PlayerVisual.set_lean()`;
- зовёт `move_and_slide()`; вертикаль — через гравитацию (`gravity_step`) + приземление на
  пол-коллайдер (`is_on_floor()`, `floor_snap_length`), **не** ручной пин Y — так вертикальный поп
  нокбэка (`fallen`) отыгрывается физикой, а не сплющивается.

## API

- `set_move_intent(dir, speed_scale)` — единственный вход движения.
- `set_control_locked(on)` — при commit-действиях (пас/удар) и собственном слайде подкатчика: скорость
  **мгновенно в ноль** (не глайд), чтобы два источника движения не дрались.
- `find_on(node)` (static) — канонический «найди мой мотор» для ИИ и `match_manager._player_motor()`;
  не сканируй `get_children()` руками.
- `set_locomotion(velocity)` кормит [[презентация-и-ассеты|PlayerVisual]] скоростью для выбора стейта.
- **Спринт** (hold Shift) — просто больший `speed_scale` из человеческого пути ввода; ИИ не спринтует
  (кроме give-and-go, см. [[пас]]).
- Чистые статические функции (`desired_velocity`, `integrate_velocity`, `smooth_yaw`, `lean_deg`,
  `smooth_scalar`) headless-тестируемы, `FootballConstants` не читают.

## Слои коллизий — три раздельные группы

Умышленно разделены:

- **Слой 1** — питч и **мяч** (мяч оставлен здесь, чтобы детект гола/подката-`Area3D`,
  проверяющий `body == ball`, не ломался).
- **Полевые игроки** — на `PLAYER_COLLISION_MASK` (bit2), mask = `PLAYER_COLLISION_MASK |
  BOUNDARY_COLLISION_LAYER` (**не** слой 1) → `move_and_slide()` толкает их друг о друга и о стены,
  но не о мяч.
- **Стены-границы** (`_setup_boundaries`) — на `BOUNDARY_COLLISION_LAYER` (bit3), невидимы для *слоя*
  мяча, но мяч маскирует их и отскакивает.

**Мяч↔игрок коллизия FLIGHT-гейтед**: маска игрока никогда не включает слой мяча (ходят свободно);
мяч добавляет бит игрока только в `FLIGHT` (см. [[мяч-и-дриблинг]]) — так удар/пас физически бьётся
об игроков (блок/перехват), а дриблируемый/ничейный мяч прозрачен для капсул. Это лечение бага, где
дриблируемый мяч сталкивался с капсулой самого владельца → статтер контроля + толчок на спавне.

Тюнинг — `LOCO_*` в [[константы]]. Тесты: `check_player_motor_math.gd`,
`check_player_motor_locked_gravity.gd`.
