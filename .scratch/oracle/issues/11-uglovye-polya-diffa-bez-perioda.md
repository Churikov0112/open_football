# 11 — Дифф трасс сравнивает угловые поля без учёта периода 2π

Status: needs-triage
Type: bug

**Найдено** при приёмке фазы 5 (тикет 07, 2026-08-04). Дефект **инструмента**, не порта: ни одна
строка портированного геймплея с этим не связана.

**Симптом.** В отчёте диффа на паре `walk_line` поле `angle` получило «макс |Δ| 6.283167». Разбор по
данным: тик 110, эталон `-3.141574`, порт `3.141593`. Это **один и тот же угол** — разные стороны
±π, — а инструмент печатает расхождение почти в два π.

**Причина по коду.** `tools/oracle_trace.gd`, непрерывный слой считает `absf(float(a) - float(b))`
одинаково для всех классов полей. Для позиции и скорости это верно, для `angle` и `rel_body_angle` —
нет: величина периодична, и сравнивать надо по кратчайшей дуге,
`abs(wrapf(a - b, -PI, PI))`.

**Чем это опасно на самом деле.** На этом прогоне вердикт не пострадал — рост `angle` с тика 1
настоящий (стороны стоят на разных клипах с нулевого тика, тикет 10), а печатаемый максимум лишь
вводит в заблуждение. Но правило начала роста смотрит на |Δ|, и обратный случай реален: две стороны,
идеально совпадающие по углу, но колеблющиеся вокруг ±π, дадут ряд из чередующихся 0 и 6.28.
Монотонного роста он не даст, то есть ложного вердикта скорее всего не будет, — а вот **обратная
ошибка гарантирована**: настоящий рост угла, пересёкший ±π, обрывается скачком вниз, окно «не убывает»
рвётся, и начало роста не называется вовсе. Инструмент промолчит там, где обязан говорить.

**Почему не починено сразу.** Приёмка фазы 5 (тикет 07) измеряет, а не чинит; правка инструмента в её
рамках размыла бы вердикт, снятый уже работающей версией. Порядок починки — за человеком.

**Blocked by:** None.

- [ ] Вердикт на паре `walk_line` переснят: максимум по `angle` перестал быть 6.28
