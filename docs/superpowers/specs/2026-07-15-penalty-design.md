# Пенальти — дизайн (Фазы A / B / C)

**Дата:** 2026-07-15
**Статус:** Фаза A — к реализации; Фазы B и C — проектные разделы «на вырост» (в этом спеке зафиксированы, реализуются отдельными планами позже).

## Что делаем

Механику пенальти в три фазы, разнесённые во времени:

- **Фаза A — исполнение пенальти за бьющего** (реализуем по этому спеку). Пользователь целится и бьёт; вратарь прыгает вслепую.
- **Фаза B — отражение пенальти за вратаря** (проект). ИИ бьёт; пользователь в окне перед ударом выбирает стиком направление прыжка.
- **Фаза C — серия пенальти** (проект). Отдельный контроллер серии оркеструет одиночные пенальти, ведёт счёт/кружки/эмоции.

Общий принцип раздела ответственности: **базовый `PenaltyController` умеет разыграть ровно ОДИН пенальти и ничего не знает про серию.** Специфика серии (классификация исхода, счёт, цветные кружки, анимации радости/грусти) живёт в отдельном `PenaltyShootoutController`, который внутри себя гоняет базовые контроллеры.

## Контекст поля (существующий код)

- Ворота: `Vector3(0,0,±field_length)` (Home на −Z, Away на +Z). Атакуемые человеком ворота — те, где стоит вратарь: `keeper.goal_line_z = -field_length` (см. `match_manager._setup_keeper`). Человек атакует к −Z.
- Точка пенальти = `Vector3(0, BALL_RADIUS, goal_line_z + into_field * PENALTY_SPOT_DIST)`, где `into_field = +1` для ворот на −Z, `PENALTY_SPOT_DIST = 11.0` (уже в константах). 11-метровая отметка сейчас только рисуется разметкой — игрового узла-маркера нет; контроллер вычисляет точку из констант, к mesh разметки не привязывается.
- Переиспользуемое из готового кода: заряд/удар (`_fire_shot`, `ShotSystem.ballistic_to`), черпачок (`PassSystem.launch_lob`), commit-путь удара через сигнал `PlayerVisual.action_contact` + `ball.launch`, автомат вратаря с нырками (`keeper_ai.gd`: `_begin_save`/`_dive`/контакт, `KeeperLogic.resolve_save`, разброс `KEEPER_SAVE_ERROR`), детекция гола `GoalArea.body_entered` + празднование сетки + `_reset_ball`, построение ввода в коде (`_setup_inputs`), константы камеры от 3-го лица (`CAMERA_TP_*`).

## Архитектура

Соответствует принятому в проекте расколу «геймплей ↔ чистая тестируемая математика» (как `PassSystem`/`KeeperLogic`/`NetSim`).

**Новые файлы:**

- `scripts/match/penalty_controller.gd` (`extends Node`) — базовый оркестратор ОДНОГО пенальти. Добавляется в `match.tscn` из `match_manager._ready()`. Держит автомат `SETUP → AIM → STRIKE`, ссылки (мяч, вратарь, бьющий, камера, HUD-маркер) и `_pen_rng` (seedable `RandomNumberGenerator`).
- `scripts/match/penalty_logic.gd` (`class_name PenaltyLogic extends Object`) — чистая математика, **никогда не читает `FootballConstants`** (тюнинг параметрами), headless-тестируемо.
- `tests/check_penalty_logic.gd` — тест чистых функций.
- `scripts/match/penalty_shootout_controller.gd` — **Фаза C, не пишем сейчас** (описан в разделе Фаза C).

**Правки существующих файлов:** `match_manager.gd` (флаг `_penalty_active` + `is_penalty_active()` + делегация + триггер по кнопке P), `keeper_ai.gd` (`set_penalty_mode()` / `begin_penalty_dive(zone)`), `match_camera.gd` (`set_penalty_view()`), `player_visual.gd` (root motion для `penalty_kick_l/_r` + выбор ноги), `tools/merge_mixamo.py` (не морозить эти два клипа), `football_constants.gd` (секция `PENALTY`), плюс CLAUDE.md / AGENTS.md.

**Глушение обычных систем.** Пока `match_manager._penalty_active == true`:
- `_handle_player_input` не трогает бьющего (ввод обрабатывает контроллер);
- следящая камера уступает фикс-пенальти-виду;
- полевой ИИ (`simple_ai` / `teammate_ai`) стоит (гейт по флагу, как уже сделано для `is_celebrating()`);
- вратарь в пенальти-подрежиме (`set_penalty_mode(true)`) — не читает траекторию, держит центр.

## Фаза A — исполнение пенальти за бьющего (реализуем)

### Автомат

Пенальти-режим живёт **только до удара**:

```
IDLE → SETUP → AIM → STRIKE → (мяч в игре) → IDLE
```

- **SETUP** — расставляет актёров (ниже), переключает камеру в фикс-режим, `controlled_player = бьющий`, маркер прицела в центр ворот, `keeper.set_penalty_mode(true)`, `_penalty_active = true`.
- **AIM** — стик двигает маркер; удержание кнопки удара копит силу (жёлтый круг растёт); `combo_modifier`+удар помечает вариант «черпачок». Отпустил (или полный заряд) → STRIKE.
- **STRIKE** — семплим итоговую точку, считаем вектор запуска, играем `penalty_kick_l/_r` (root motion), на `action_contact` → `ball.launch(...)` **и** `keeper.begin_penalty_dive(zone)` (слепой нырок). Сразу после — если `release_after_strike == true` (одиночный), снимаем пенальти-режим: камера/ввод/полевой ИИ/вратарь → норма. Мяч — живой.

**После удара всё делают обычные системы, не контроллер.** Гол ловится штатным `GoalArea.body_entered` → штатное празднование → `_reset_ball` (мяч в центр поля, обычный ввод — это и есть «гол → центр поля»). Сейв — вратарь доигрывает нырок и контактом решает ловля/отбой (существующая геометрия). Промах — мяч катится, игра идёт по обычным правилам. **Никаких RESOLVE / классификации / таймаута в базовом контроллере для одиночного пенальти** (это нужно только серии — см. Фаза C).

### Расстановка (SETUP)

Обобщённо, работает при любом текущем составе:

- **Мяч** — на 11-метровую точку атакуемых ворот (формула выше), центр по X.
- **Бьющий** = текущий `controlled_player` (team_1). Ставится за мячом по A1-расстоянию `точка_удара − facing × PEN_RUNUP_DIST`, лицом к воротам, в **обычном idle** (разбег стартует только на STRIKE).
- **Вратарь** — по центру линии (x=0), уже там; переводим в `set_penalty_mode(true)` — держит центр во **вратарском idle** (`keeper_idle`), траекторию не читает.
- **Прочие полевые** (оба состава, кроме бьющего и вратаря) — за дугу штрафной (радиус ≥ `PENALTY_AREA_DEPTH` от линии, вне «D»). В текущем дебаг-состоянии реальных таких почти нет (тиммейт/соперник отключены, есть стенка-болванки) — расстановка «best-effort», не жёсткое требование; болванки далеко, их не трогаем.

### Прицел и разброс

FIFA-подобный **свободный маркер на плоскости ворот** (z = `goal_line_z`):

- Стик задаёт скорость маркера по X (ширина) и Y (высота); позиция интегрируется и клампится в рамку **с небольшим овершутом за штанги/перекладину** (чтобы можно было осознанно целиться впритирку и промахнуться). Старт — центр ворот.
- Круг разброса растёт с зарядом силы: `R = lerp(PEN_SPREAD_MIN_R, PEN_SPREAD_MAX_R, charge_ratio)`. Сильнее удар → быстрее мяч → больше круг.
- Итоговая точка = `aim_point + равномерный семпл внутри диска радиуса R`. Вышел за рамку → мяч мимо/над. Так «можно промахнуться» получается из двух источников: осознанный увод маркера к штанге + большой круг на полной силе.
- Кольцо прицела — **жёлтое** (заметнее для тестов).

### Математика (`PenaltyLogic`, чистые функции)

- `move_reticle(cur: Vector2, stick: Vector2, speed, dt, half_width, height, overhang) -> Vector2` — интеграция позиции маркера + кламп в рамку+овершут.
- `spread_radius(charge_ratio, min_r, max_r) -> float` — радиус круга от заряда (монотонно растёт).
- `sample_in_disc(center: Vector2, radius, rng: RandomNumberGenerator) -> Vector2` — равномерный семпл в круге (радиус через `sqrt(u)`, иначе центр перегружен).
- `power_speed(charge_ratio, min_speed, max_speed) -> float` — скорость мяча от заряда.
- `plane_point_to_world(xy: Vector2, goal_center: Vector3, goal_line_z) -> Vector3` — точка плоскости ворот → мир.
- `random_dive_zone(rng) -> int` — 1 из 5 (`enum Zone { LOW_L, HIGH_L, LOW_R, HIGH_R, CENTER }`).
- `zone_target(zone, goal_center, half_width, height, low_y, high_y, lateral) -> Vector3` — репрезентативная точка зоны, куда целит нырок вратаря.

Вектор запуска переиспользуем: прямой удар — `ShotSystem.ballistic_to(from, target3d, power_speed, gravity)`; черпачок — `PassSystem.launch_lob(from, target3d, peak, gravity)`. Кручёный на пенальти в Фазе A **не делаем** (инфраструктура `launch_curl` остаётся на потом).

Все `RandomNumberGenerator` — через явный seedable-параметр (`_pen_rng`), чтобы тест был детерминирован.

### Root-motion анимация удара (`penalty_kick_l` / `penalty_kick_r`)

Клипы удара — **с разбегом** (root motion), в отличие от всех прочих клипов, замороженных «на месте» через `IN_PLACE_CLIPS`. Два клипа: левая нога (`penalty_kick_l`) и правая (`penalty_kick_r`), переиспользуются позже для штрафных ударов.

**Почему root motion, а не кодовое движение тела (как везде в проекте).** Клип содержит реальные шаги подхода (разгон → постановка опорной → удар). Если снять root motion и гнать тело кодовой скоростью (клип «на месте», как через `IN_PLACE_CLIPS`), ноги переступают на месте, пока тело едет → foot-slide («лунная походка» к мячу). Проектный анти-слайд `run_timescale = speed/top × fudge` спасает только зациклённый бег с **постоянной** кодовой скоростью; у разбега-с-ударом скорость непостоянна, и подогнать её под переменный шаг клипа нереально. Root motion решает это бесплатно: позиция тела следует за стопами точно так, как задумал аниматор (постановка опорной и контакт с мячом синхронны с перемещением) — это каноничное применение root motion. Цена — одна: эмпирически выверить ось/масштаб извлечения (грабль Mixamo из CLAUDE.md), что попутно делает скрипт замера `PEN_RUNUP_DIST`. Это **второе намеренное исключение** из кодового движения (первое — `move_and_collide` в подкате) и так же well-contained: один one-shot клип, ось выверена один раз. (Если бы клип был «плант + удар» почти без перемещения — наоборот, root motion не нужен: предрасставить у мяча и играть на месте. Но здесь полноценный разбег.)

**Модель A1 — root motion применяется к телу:**

1. **Не добавляем** `penalty_kick_l/_r` в `IN_PLACE_CLIPS` в `tools/merge_mixamo.py` — сохраняем их поступательное перемещение в собранном `.glb`.
2. В `PlayerVisual` для этих клипов включаем `root_motion_track` (корневая кость); каждый кадр отдаём извлечённый сдвиг наружу (новый API, напр. `consume_root_motion() -> Vector3`); во время STRIKE его применяет контроллер/мотор к `CharacterBody3D` (по образцу «мотор залочен, движением владеет другой код», как `move_and_collide` в подкате). Тело и модель едут вместе, стопа приходит к мячу на кадре контакта, **после удара модель не «прыгает» назад** к телу.
3. **Пред-расстановка** бьющего = `точка_удара − facing × PEN_RUNUP_DIST`. `PEN_RUNUP_DIST` (суммарный горизонтальный сдвиг корня за клип) и кадр контакта **замеряем эмпирически** одноразовым headless-скриптом по факту собранного glb (сэмплируем `Position3D`-трек корневой кости) — ровно как советует CLAUDE.md про `IN_PLACE_CLIPS` (ось/масштаб Mixamo легко угадать неверно). Результат кладём в константы / `ACTION_TIMING`.

**Выбор ноги** — параметр удара (по умолчанию правая, `penalty_kick_r`); прокидывается как аргумент в `trigger`/strike, чтобы штрафные потом выбирали ногу. Оба клипа регистрируем в `ACTION_CLIPS` с их индивидуальным `ACTION_TIMING`.

### Поза ожидания и смена бьющего (только одиночный пенальти)

Во время AIM (до разбега) бьющий стоит в **обычном idle**, а не в кадре 0 клипа удара; вратарь — во **вратарском idle** (`keeper_idle`). Разбег и удар начинаются только на STRIKE: одноразовый триггер `penalty_kick_l/_r` из idle несёт игрока к мячу root motion'ом. Отдельная «пенальти-стойка» (кадр 0 клипа) не нужна.

**Смена бьющего по ходу розыгрыша (future, только одиночный).** В будущем во время одиночного пенальти можно будет сменить `controlled_player` на другого бьющего. Новый бьющий может быть с другой ноги, поэтому пенальти-режим должен уметь на лету сменить **клип удара** (`penalty_kick_l` ↔ `penalty_kick_r`) и **пере-расставить** бьющего по `PEN_RUNUP_DIST` соответствующего клипа (разбег/контакт могут отличаться по ноге — замеряем оба клипа). Поза ожидания — общий idle, от ноги не зависит.

Смена бьющего по ходу доступна **только в обычном (одиночном) пенальти**. В серии порядок бьющих фиксируется заранее, до первого удара (см. Фаза C). Шов закладываем сейчас (нога/клип — параметр удара); саму фичу смены бьющего в первом плане Фазы A можно не реализовывать — уточним при планировании.

### Слепой нырок вратаря

Момент коммита нырка привязан к удару, а не к чтению мяча: контроллер зовёт `keeper.begin_penalty_dive(zone)` **на `action_contact`** — визуально вратарь реагирует «в последний момент», но зону выбрал вслепую (`PenaltyLogic.random_dive_zone`). Внутри `begin_penalty_dive`:

- **Угловые зоны** (`LOW_L/R`, `HIGH_L/R`) — синтезируем `dec = {action, target = zone_target(...)}` и вызываем **существующую** машинерию `_begin_save` → `_dive` → контакт; ловля/отбой по зоне+скорости через `resolve_save`;
- **`CENTER`** (вратарь остался по центру, не прыгнул) — заходим в **существующий центральный путь**, а не в кастомную «стой и лови». Если удар идёт по центру (в радиус рук по X), ловля/промах решаются **теми же правилами по высоте, что и при обычном ударе с игры**: `_should_catch_high` + `_catch_clip_for_height` — низом `keeper_scoop`, на уровне живота/груди `keeper_catch`, на уровне головы `keeper_catch_head`, выше головы `keeper_catch_top`; а в полосе выше `KEEPER_HIGH_CATCH_CERTAIN` — **иногда не берёт** (`miss_top`, монетка `KEEPER_HIGH_CATCH_CHANCE`). Т.е. `begin_penalty_dive(CENTER)` роутится в `_begin_central_catch` / `_begin_miss_top`;
- нырок держим фиксированное время (≈ длина клипа), т.к. траекторию мяча заранее не считаем;
- внутри снимаем `penalty_mode`, так что после нырка вратарь сам вернётся к штатному `_position`.

**`set_penalty_mode(true)` нужен только чтобы во время AIM/удара вратарь не нырял реактивно** (иначе «угадайка» ломается — он бы видел, куда летит мяч). Он снимается на коммите нырка, поэтому гонки кадров нет.

**Разрешение «поймал / отбил / гол» = существующая геометрия.** `_dive`/контакт уже проверяют `_catch_radius_hit` и `resolve_save` (ловля/отбой по зоне+скорости) с джиттером `KEEPER_SAVE_ERROR`. Отсюда бесплатно получаем требование: **угадал сторону, но мяч в девятке / сильный — всё равно гол.** Отдельной таблицы вероятностей не нужно.

### Камера

Фикс-вид, не следящий. В `match_camera.gd` — режим `set_penalty_view(kicker_pos, goal_center)`: паркует камеру **за бьющим** (позади точки, по линии мяч→ворота), приподнято, `look_at` в ворота чуть выше газона — в кадре бьющий + мяч + ворота. Позиция/высота/наклон — константы (старт от `CAMERA_TP_*`). Держится весь розыгрыш (AIM→STRIKE); при `release_after_strike` возвращаем обычную следящую камеру на ударе. Логика камеры — в одном месте (`match_camera`), контроллер только зовёт метод.

### HUD

Мир-спейс, на плоскости ворот (по образцу существующего жёлтого `_target_indicator`):

- **Маркер прицела** — жёлтое кольцо на плоскости ворот в точке прицела.
- **Круг разброса** — радиус кольца = `PenaltyLogic.spread_radius(charge_ratio)`; растёт при заряде. Это и есть визуализация «больше сила → больше разброс».
- **Полоса силы** — переиспользуем существующий `power_bar`.
- **Флаг видимости** `_reticle_visible` — **future**: быстрое скрытие кольца, чтобы при игре вдвоём за разные команды на одном экране у вратаря не было преимущества. В Фазе A всегда `true`, но HUD читает один флаг — чтобы потом повесить тумблер без переделки.

### Ввод

Пока `_penalty_active`, кнопки перехватывает контроллер (обычные `_start_charge`/`_handle_player_input` для бьющего заглушены):

- **Прицел** — `move_*` (стрелки / левый стик).
- **Заряд силы** — `kick` (D / геймпад-X): удержание копит, отпускание / полный заряд → удар.
- **Черпачок** — `combo_modifier` + `kick` (LB+X на геймпаде; Q+D на клавиатуре) — тот же заряд/прицел, ветка `launch_lob`.
- **Триггер теста** — новый action `penalty_debug` (клавиша **P**), добавляем в `_setup_inputs`; в `_physics_process` при нажатии и `not _penalty_active` — старт розыгрыша в атакуемые ворота.

### Константы (новая секция `PENALTY` в `football_constants.gd`)

- `PEN_RUNUP_DIST` (замеряем эмпирически из клипа), нога по умолчанию.
- `PEN_RETICLE_SPEED`, овершут рамки прицела по X/Y.
- `PEN_SPREAD_MIN_R`, `PEN_SPREAD_MAX_R` (радиус круга мин/макс сила).
- `PEN_POWER_MIN_SPEED`, `PEN_POWER_MAX_SPEED`, `PEN_CHARGE_MAX_TIME`.
- `PEN_CHIP_PEAK_MIN` / `PEN_CHIP_PEAK_MAX` (или переиспользуем `CHIP_*`).
- `PEN_KEEPER_DIVE_LOW_Y`, `PEN_KEEPER_DIVE_HIGH_Y`, `PEN_KEEPER_DIVE_LATERAL` (репрезентативные точки зон нырка).
- Празднование/возврат — переиспользуем `NET_CELEBRATION_TIME`.

### Шов `release_after_strike`

Единственный шов базового контроллера наружу:

- **Сигнал `struck`** — испускается на ударе; на этом базовый контроллер останавливается, сам не решает, что дальше.
- **Флаг `release_after_strike`** (по умолчанию `true`):
  - `true` (одиночный, Фаза A): на `struck` контроллер сам снимает пенальти-режим (камера/вратарь/ввод → норма), мяч уходит в обычную игру, исход разрулят штатные системы. Классификации внутри нет.
  - `false` (в серии, Фаза C): после удара контроллер **остаётся собранным** (камера-фикс, вратарь в пенальти-рамке), не трогает обычную игру — тир-даун делает владелец (`PenaltyShootoutController`).

Кто владелец после удара — решает вызывающий: `match_manager` для одиночного, `PenaltyShootoutController` для серии.

## Фаза B — отражение пенальти за вратаря (проект)

Переиспользует базовый `PenaltyController`, меняя, кто чем управляет: **бьющий — ИИ, вратарь — человек (только направление).**

- **Бьющий = ИИ:** контроллеру нужен авто-путь удара — ИИ выбирает точку прицела, силу и вариант (прямой/черпачок), затем тот же STRIKE. Прицел ИИ пользователю **не показываем** (иначе нечестно) — используем флаг `_reticle_visible = false`.
- **Вратарь = человек:** перед ударом ИИ — «комфортное окно» ввода, где пользователь **удерживает левый стик** и выбирает направление прыжка. Куда направлен стик на момент удара — туда `zone` для `begin_penalty_dive(zone)` (вместо `random_dive_zone`). Пользователь только выбирает направление; нырок/ловлю/отбой делает вратарь сам.
- **«Угадал ≠ отбил»** — та же геометрия (`resolve_save` + `KEEPER_SAVE_ERROR`): даже верное направление не гарантирует сейв.
- **Камера** — вероятно из-за спины/сбоку вратаря (кадрирование под вратарский обзор); уточним в плане Фазы B.
- **Шов** — окно ввода направления + источник `zone` (стик vs random) параметризуются в базовом контроллере; автомат/удар/нырок переиспользуются.

## Фаза C — серия пенальти (проект)

Отдельный `scripts/match/penalty_shootout_controller.gd`, который **внутри себя создаёт/гоняет базовые `PenaltyController`** (по одному на удар, с `release_after_strike = false`) и держит всю специфику серии.

- **Классификация исхода.** Обычной игры между ударами нет — поле «заморожено», поэтому исход каждого удара контроллер серии определяет сам: ловит `struck`, следит за мячом, классифицирует **гол / сейв / промах** (+страховочный таймаут против зависшего состояния — мяч попал в штангу и укатился, отбит под странным углом и замер и т.п.). Геометрические предикаты (мяч за линией в створе / вне рамки / встал не дойдя) выносим в чистые функции (`PenaltyLogic`), цикл-ожидание с таймаутом — в контроллере серии.
- **Счёт и правила.** Best-of-5 с чередованием сторон, при равенстве — внезапная смерть (по правилам серии пенальти). Досрочное завершение, когда результат уже не догнать.
- **Индикатор серии** — по 5 кружков на команду, зелёный = забит, красный = не забит (как на референсе).
- **Эмоции** — анимации радости/грусти бьющего и вратаря по исходу (клипы добавим позже).
- **Тир-даун** — камера/вратарь/HUD собраны на всю серию; общий возврат к норме только в конце серии.
- **Порядок бьющих фиксируется заранее**, до первого удара серии (список игроков на 5 ударов + порядок внезапной смерти). Смены бьющего по ходу серии, в отличие от одиночного пенальти, **нет** — контроллер серии просто идёт по заготовленному списку.
- **Чередование бьющих/сторон** и вратарский/бьющий состав — слой контроллера серии, базовый об этом не знает.

Таким образом вся логика серии (ожидание исхода, классификация, счёт, кружки, эмоции) изолирована в `PenaltyShootoutController`, а базовый контроллер остаётся минимальным: «разыграть один пенальти и сообщить `struck`».
