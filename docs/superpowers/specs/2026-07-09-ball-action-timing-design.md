# Тайминг действий с мячом: точное касание + короткий замах

## Обзор

Этап 3 (футбольные анимации) свёл удар/пас на клип `pass` через commit-механизм в
`match_manager` (`_start_ball_action`/`_tick_ball_action`). Приёмка выявила два дефекта:

1. **Рассинхрон касания.** Импульс мячу применяется на угаданной доле `0.45 * длина_клипа`,
   а не в кадр касания ногой → мяч улетает раньше/позже, чем нога бьёт.
2. **Уязвимость на замахе.** Замах длинный, игрок стоит колом → соперник (скорость 6.5 против
   8.0 у игрока) догоняет и отбирает мяч.

Это **точечный фикс** аркадной модели. Полный реализм движения (инерция, разгон/торможение,
root motion, foot IK, motion-matching) — сознательно **вне области**, отдельный спек и
отдельная ветка (см. «Follow-up»).

## Область

**В области:**
- Точное касание мячом в момент удара ногой (для паса/удара человека).
- Короткий замах у паса.
- Корректная отмена действия, если игрока сбили во время замаха.

**Вне области (осознанно):**
- Инерция/follow-through, «быстрый пас vs силовой удар», защита мяча на замахе — рассмотрены и
  отклонены для этого фикса.
- Удары ИИ (`simple_ai._kick_towards_goal`) остаются мгновенными (`ball.kick` напрямую).
  Несоответствие «ИИ мгновенно, человек с замахом» принимаем временно; выравнивается в
  полном реализме.
- Любая переработка локомоции.

## Принятые решения

| Решение | Причина |
|---|---|
| Тайминг касания живёт в `PlayerVisual`, не в `match_manager` | Визуал знает клип; чистое разделение геймплей/презентация; переживёт замену клипа |
| Геймплей реагирует на **сигналы** визуала, а не считает долю сам | Убирает угаданную `0.45`; момент касания — свойство клипа |
| Короткий замах — тюнингом чисел в одном месте (конфиг в `PlayerVisual`) | Минимальный объём; настраивается на глаз без правки логики |
| Скорость проигрывания действия — отдельный рычаг | Чтобы сжать медленный клип, сохранив синхрон «касание = вылет мяча» |

## Архитектура

### `PlayerVisual` — источник тайминга действия

Новый публичный контракт (в дополнение к текущим `trigger`/`set_locomotion`/…):

```gdscript
signal action_contact(action: String)    # момент касания мячом ногой
signal action_finished(action: String)   # действие завершилось, управление можно вернуть

## Тайминг на действие. Значения — тюнятся визуальной приёмкой.
##   contact — секунды от старта действия (в реальном времени, с учётом speed) до касания;
##   lock    — сколько всего длится действие (до action_finished);
##   speed   — множитель скорости проигрывания клипа (сжать замах, сохранив синхрон).
const ACTION_TIMING := {
    "pass": { "contact": 0.2, "lock": 0.4, "speed": 1.5 },
}
```

Поведение `trigger(action)`:
- `travel` в one-shot стейт (как сейчас) с применением `speed` к проигрыванию этого стейта
  (через масштабирование времени в `AnimationTree` — конкретный узел определит план);
- запустить внутренние таймеры (в реальном времени): по `contact` → `emit action_contact(action)`;
  по `lock` → `emit action_finished(action)`;
- если для действия нет записи в `ACTION_TIMING`, взять `contact = 0`, `lock = action_length`,
  `speed = 1.0` (безопасный дефолт — старое поведение «сразу»).

`speed` и `contact` связаны: `contact` задаётся в реальных секундах и должен совпасть с
моментом, когда нога визуально касается мяча при данном `speed`. Тюнинг: `contact` двигает
«когда вылетает мяч», `speed` двигает «как быстро идёт замах».

### `match_manager` — реакция на сигналы

`_start_ball_action(player, dir, power, action)`:
- развернуть игрока по `dir` (как сейчас);
- запомнить `_action_dir`, `_action_power`, `_action_player`, взвести `_action_lock` (флаг «идёт»);
- `visual.trigger(action)`;
- подписаться на сигналы **этого** визуала: `action_contact` и `action_finished`
  (одноразово, с `bind(player)` — чтобы обработчик знал игрока).

Обработчики:
- `_on_action_contact(action, player)` → если действие не отменено: `ball.kick(_action_dir, _action_power)`.
- `_on_action_finished(action, player)` → снять блокировку управления (`_action_player = null`).

Блокировка управления в `_handle_player_input` — как сейчас (ранний выход, пока действие идёт).
Покадровый таймер `_tick_ball_action` **удаляется** — тайминг теперь в сигналах визуала.

### Отмена действия

Если во время действия игрок попал в группу `fallen` (сбит) или начался его подкат:
- пометить действие отменённым → `action_contact` **не** бьёт мяч;
- снять блокировку и подписки.

Проверяется в момент `action_contact` (флаг отмены) и при входе в `fallen`/подкат
(явный вызов отмены). Иначе мяч «выстрелит» из-под лежащего игрока.

## Поток данных

```
Space/E → _kick_ball/_pass_ball → _start_ball_action(dir,power,"pass")
   ├─ player.rotation.y = к dir
   ├─ visual.trigger("pass")  →  AnimationTree travel + таймеры (contact, lock)
   ├─ подписка на visual.action_contact / action_finished
   └─ управление заблокировано (_handle_player_input рано выходит)

visual.action_contact("pass")  → ball.kick(dir, power)      # мяч летит в кадр касания
visual.action_finished("pass") → _action_player = null      # управление вернулось
(сбит/подкат во время замаха) → отмена → импульс не применяется
```

## Тестирование

- **Headless** (`tests/`): `PlayerVisual` для `pass` отдаёт `contact > 0` и `lock > 0`;
  сигналы `action_contact`/`action_finished` объявлены; проект грузится без `SCRIPT ERROR`.
  (Точную синхронность «нога↔мяч» headless не видит.)
- **Визуальная приёмка (пользователь):**
  1. мяч улетает в момент касания ногой, не раньше/позже;
  2. пас быстрый, замах короткий;
  3. соперник не успевает отобрать мяч на замахе;
  4. если по бьющему проходит подкат во время замаха — мяч не вылетает.
- Тюнинг: `ACTION_TIMING["pass"]` — три числа (`contact`, `lock`, `speed`).
