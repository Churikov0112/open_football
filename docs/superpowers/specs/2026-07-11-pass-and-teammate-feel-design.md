# Дизайн: ощущение пасов + поддержка ИИ-тиммейта

## Проблема

После Фазы 2 (очередь ударов/пасов) стало тяжело тестировать из-за трёх связанных проблем ощущения,
подтверждённых плейтестом и диагностикой кода:

1. **Слабый пас, особенно короткий.** `PassSystem.ground_pass_speed` выводит скорость как
   `дистанция / время_полёта` с полом `PASS_GROUND_MIN_SPEED = 6` м/с. На короткой дистанции при
   малом заряде скорость упирается в пол — мяч еле катится.
2. **«Из ноги в ногу вблизи».** После паса `_fire_pass` сразу передаёт управление принимающему
   (`controlled_player = receiver`, `_receive_active`), и receive-assist ведёт его к
   `ball.pos + ball.linear_velocity * PASS_RECEIVE_PREDICT_WINDOW(0.04с)` ≈ **текущая** позиция мяча.
   При медленном пасе мяч ещё у ног отдавшего → принимающий бежит **назад** к отдавшему, встречаются
   вплотную.
3. **ИИ-тиммейт «бежит в мяч».** `teammate_ai._chase_ball` гонит прямо в мяч, когда мяч не у
   носителя-человека. Позицию поддержки (`_position_for_pass`, ~10 м впереди) держит только при
   `ball.dribbler == controlled_player`.

Направление паса (авто-выбор цели) пользователь сознательно отложил — вероятно, подтянется вслед за
силой паса; в этот дизайн не входит (кроме того, что от него зависит).

## Референс: как сделано в OpenSoccer (`C:\Users\User\Desktop\OpenSoccer`)

- **Сила (`SmartBall._passBall`):** прямой импульс к цели `clamp(distance * 1.5, minPassSpeed=75,
  maxPassSpeed=110)` + лёгкий подъём `(0, 5, 0)`. Жёсткий минимум → любой пас, включая короткий,
  уходит твёрдо.
- **Приём (`AI.pcollectState`):** принимающий ведёт **скорость мяча** — если мяч летит почти прямо в
  него (`abs(dot) > 0.95`) цель = `ballpos`, иначе `ballpos + ballvel * dSmart`. Выходит вперёд на
  пас, а не назад.
- **Поддержка (`AI.supportState`):** держит формационную позицию с расстановкой (отходит, если
  слишком близко к цели паса), к мячу идёт только в ролях PCOLLECT/PRESS/INTERCEPT — не гонит в мяч.

## Решение

Три связанных изменения (твёрдый пас → у мяча есть скорость → принимающий ведёт её вперёд → выходит на
пас, а не назад; тиммейт предлагает себя, а не липнет к мячу).

### 1. Сила паса — твёрдый пейс (модель «firm minimum»)

Низовой пас (`ground`, не `is_air`) получает **твёрдый минимум пейса** независимо от дистанции; заряд
добавляет пейс/дальность сверху.

- Поднять `PASS_GROUND_MIN_SPEED` с `6` до `~15` м/с (тюнинг-старт) — нижняя граница `clamp` в
  `PassSystem.ground_pass_speed`. Модель функции («скорость = дистанция / время, зажатая в
  [min,max]») сохраняется; поднятый пол гарантирует, что короткий/слабозаряженный пас всё равно
  крепкий. `PASS_GROUND_MAX_SPEED` (40) без изменений.
- Слегка ужать `PASS_GROUND_MAX_TRAVEL_TIME` (0.9 → ~0.7с), чтобы минимально-заряженный пас на
  средней дистанции тоже был живее (меньше «мягкого» диапазона). `PASS_GROUND_MIN_TRAVEL_TIME` (0.3)
  без изменений.
- Лёгкий подъём мяча с газона при пасе (как `(0,5,0)` в OpenSoccer, но мягче — низовой должен
  остаться низовым): добавить малую вертикальную составляющую в `PassSystem.launch_ground` (параметр
  `up`), значение из новой константы `PASS_GROUND_LIFT` (~1.5 м/с, тюнинг-старт).
- **Навесы/лобы (`is_air`, `launch_lob`) не трогаем** — там сила уже задаётся высотой дуги и
  дистанцией; проблема только у низовых.

`PassSystem.ground_pass_speed`/`launch_ground` остаются чистыми функциями (тюнинги параметрами,
headless-тест `tests/check_pass_system_math.gd`).

### 2. Приём — вести скорость мяча (fix «из ноги в ногу»)

Принимающий целится в **точку перехвата по ходу мяча**, а не в текущую позицию мяча.

- Новая чистая функция `PassSystem.receive_point(receiver_pos, ball_pos, ball_vel, lead_time,
  on_line_dot) -> Vector3`:
  - `dir_to_ball = (ball_pos − receiver_pos)` (плоско), `bv = ball_vel` (плоско).
  - Если `dir_to_ball.normalized().dot(bv.normalized())` по модулю выше `on_line_dot` (мяч летит
    почти прямо в/от принимающего) → вернуть `ball_pos` (встречаем на линии).
  - Иначе → вернуть `ball_pos + bv * lead_time` (ведём вперёд по ходу мяча — точка перехвата).
  - Пустая скорость мяча (`bv ≈ 0`) → `ball_pos`.
- Применяется в двух местах:
  - **Человек-принимающий:** receive-assist в `match_manager._handle_player_input` (заменить текущее
    `ball.pos + vel*PASS_RECEIVE_PREDICT_WINDOW` на `PassSystem.receive_point(...)`).
  - **ИИ-принимающий:** `teammate_ai._move_to_receive` (в ноги — та же `receive_point`).
- Новые константы: `PASS_RECEIVE_LEAD_TIME` (~0.2с, тюнинг-старт; заменяет узкое окно 0.04),
  `PASS_RECEIVE_ONLINE_DOT` (~0.9). `PASS_RECEIVE_PREDICT_WINDOW` (0.04) уходит из receive-пути (можно
  удалить, если больше нигде не используется — проверить grep).

Вместе с твёрдым пасом (у мяча реальная скорость) это даёт выход **вперёд на пас**.

### 3. ИИ-тиммейт — предлагает себя под пас (не бежит в мяч)

`teammate_ai.gd` перестаёт гнать в мяч при владении нашей команды; держит позицию поддержки.

- **Пока наша команда владеет мячом** (любой из team_1 — дриблер, не только управляемый) → держать
  позицию поддержки (обобщённый `_position_for_pass`): впереди носителя по направлению атаки + сбоку,
  на пас-дистанции (~10–12 м), с расстановкой (не приближаться к носителю ближе некоего минимума).
  Скорость — спокойная трусца (`_base_scale()`), не спринт.
- **К мячу бежать (`_chase_ball`) только когда:** мяч реально ничейный/в борьбе (никто из нашей
  команды не владеет и мяч не летит к нам как пас), **или** этот тиммейт — адресат паса (роль
  `RECEIVING` → выход на пас по `receive_point` из п.2).
- Условие выбора ветки в `_physics_process` меняется: сейчас `_position_for_pass` только при
  `has_dribbler and ball.dribbler == controlled_player`; станет «наша команда владеет» через хелпер
  «кто-то из team_1 — дриблер».
- **Гибкость под смену ворот:** направление атаки (`Vector3(0,0,-1)`) в `teammate_ai` вынести в одно
  локальное место (метод/поле `_attack_dir()`), чтобы будущий half-time-свап флипал в одной точке.
  Полная централизация на общий `_attack_dir_z` менеджера — отдельная будущая задача (вне охвата).

  `PASS_RECEIVE_ONLINE_DOT`.

  → `receive_point`; `_attack_dir()` хелпер; расстановка в `_position_for_pass`.

## Тестирование

- **Headless:** `tests/check_pass_system_math.gd` (`receive_point`, `launch_ground` с `up`) → `CHECK
  PASS`. Обе команды валидации на baseline.
- **Ручная приёмка (feel, headless не ловит):**
  1. Короткий пас — крепкий и быстрый даже лёгким тапом (не вялый накат).
  2. Пас на тиммейта — принимающий выходит **вперёд** на мяч, НЕ бежит назад к отдавшему, нет «из
     ноги в ногу».
  3. ИИ-тиммейт при нашем владении — держит позицию поддержки впереди/сбоку, предлагает себя, НЕ
     гонит в мяч.
  4. Ничейный/спорный мяч — тиммейт всё ещё идёт за ним (борьба не сломана). Требует активного
     соперника — временно `DEBUG_DISABLE_OPPONENT = false`.
- Тюнинг-ручки (финализируются живьём): `PASS_GROUND_MIN_SPEED`, `PASS_GROUND_MAX_TRAVEL_TIME`,
  `PASS_GROUND_LIFT`, `PASS_RECEIVE_LEAD_TIME`, `PASS_RECEIVE_ONLINE_DOT`, пас-дистанция/расстановка
  тиммейта.

## Вне охвата

- Авто-выбор цели паса / направление (`select_target`) — отложено пользователем.
- Полная централизация направления атаки ИИ на `_attack_dir_z` (half-time-свап) — отдельная задача.
- Полноценная OpenSoccer-модель «твёрдый импульс мимо цели, приём перехватом» — выбрали более мягкий
  «поднять пол у нашей модели arrives-at-target»; переход на импульсную модель возможен позже, если
  «пол» окажется недостаточно живым.
- Голова (Фаза 3 shot-system) — после этого.
