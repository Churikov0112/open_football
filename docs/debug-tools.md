# Debug-инструменты (тестовые леса)

Временные подпорки для ручного тестирования фич. **Оставлены намеренно** — их ещё много раз
включать по мере добавления фич. Все флаги — в `scripts/data/football_constants.gd` (секция AI,
~стр. 172–176). Свернуть перед финальным релизом фичи.

Правило: боевое поведение = все debug-флаги в дефолтных «выключенных» значениях (см. колонку
«дефолт»). Включаешь на время теста → возвращаешь обратно.

## Сводка флагов

| Флаг | Дефолт | Что делает |
|---|---|---|
| `DEBUG_BALL_TRAIL` | `true` | Цветной след за мячом (видно траекторию удара/паса) |
| `DEBUG_BALL_TRAIL_POINTS` | `90` | Длина следа в кадрах истории |
| `DEBUG_DISABLE_OPPONENT` | `false` | ИИ-соперник стоит + спавн стенок болванок |
| `DEBUG_MARK_TEAMMATE` | `false` | Соперник опекает ИИ-тиммейта (встаёт в линию паса) |
| `DEBUG_MARK_DISTANCE` | `2.5` | Дистанция маркировки (м) для режима выше |

> ⚠️ `DEBUG_BALL_TRAIL` включён по дефолту (единственный визуально активный сейчас). Остальные —
> выключены, но их код живёт в проекте и готов к включению.

## 1. Цветной след за мячом — `DEBUG_BALL_TRAIL`

Оранжево-голубая линия за мячом: видно путь удара/паса/дриблинга. Оранжевый — в полёте, голубой —
иначе; хвост затухает.

- **Код:** `match_manager.gd` → `_setup_ball_trail()` (вызывается в `_ready`), отрисовка каждый кадр
  в `_physics_process` (узлы `_trail`/`_trail_mesh`/`_trail_points`).
- **Зачем:** тюнинг траекторий (кручёный, черпачок, навесы) — видно форму дуги.
- **Выключить:** `DEBUG_BALL_TRAIL = false`.

## 2. Отключённый соперник + стенки болванок — `DEBUG_DISABLE_OPPONENT`

Когда `true`: активный ИИ-соперник просто стоит (гейт в `simple_ai._physics_process`), и спавнятся
две линии стоящих «болванок» (`WallDummy`) — стенка для теста ударов/блоков/рикошетов без
сопротивления.

- **Код:** `simple_ai.gd` (ранний `return` при флаге). `match_manager.gd` →
  `_spawn_wall_dummies()` → `_spawn_wall_line()` → `_make_dummy_opponent()` (вызывается из
  `_setup_away_player`, только при флаге). Одна стенка разрежённая (центр X=0), одна плотная (X=15).
- **Зачем:** отрабатывать удары/блок мяча об игроков, когда никто не мешает и не бегает за мячом.
- **Включить:** `DEBUG_DISABLE_OPPONENT = true`. Тогда живого соперника нет, есть только болванки.

## 3. Маркировка тиммейта соперником — `DEBUG_MARK_TEAMMATE`

Когда `true`: единственный ИИ-соперник **не гоняется за мячом/воротами**, а опекает ИИ-тиммейта —
встаёт **между мячом и тиммейтом** (в линию паса) на `DEBUG_MARK_DISTANCE` метров. Честный перехват
и подкат при этом остаются живыми.

- **Код:** `simple_ai.gd` → `_mark(delta)` (ветка в `_physics_process` при флаге), поле
  `mark_target`. Ссылка на тиммейта ставится в `match_manager._setup_teammate()` (тиммейт спавнится
  после соперника, поэтому проводка там).
- **Зачем:** тест пасов / перехватов / приёма под давлением — пасуешь тиммейту под опекой, смотришь,
  выходит ли он на мяч, срабатывает ли перехват/подкат. Требует `DEBUG_DISABLE_OPPONENT = false`
  (иначе соперник просто стоит).
- **Включить:** `DEBUG_MARK_TEAMMATE = true`.
