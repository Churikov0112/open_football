# 06 — Дифф трасс по непрерывным полям

Status: ready-for-human
Type: task

**What to build:** второй слой диффа — тот, что ловит ошибки, **не меняющие выбор клипа**. Позиция,
угол, скорость, модули смагглов, состояние мяча сравниваются с допуском, и отчёт называет тик, с
которого расхождение перестаёт быть шумом и начинает монотонно расти.

**Почему слоя два, а не один.** Побитового совпадения float между C++/MSVC и C#/.NET не существует:
другой порядок инструкций, FMA, свои реализации `sin`/`cos`/`pow`. Точное сравнение непрерывных полей
дало бы расхождение на первом же тике и обесценило инструмент. Это не временная мера и не поблажка —
двухслойность есть прямое следствие кросс-языкового порта.

**Интересен рост, а не превышение.** Отчёт печатает тик начала роста, а не каждое превышение допуска:
одиночный всплеск в пределах шума — не сигнал, а вот расхождение, которое растёт от тика к тику,
означает разошедшуюся динамику даже при совпавших клипах.

**Допуски по классам полей** (дефолты; переопределяются файлом допусков, но эти числа — стартовые):

| Класс | Колонки | Допуск |
|---|---|---|
| позиция | `pos_*` | 1e-3 (м) |
| угол | `angle`, `rel_body_angle` | 1e-3 (рад) |
| скорость | `move_*` | 1e-3 (м/с) |
| смаггл | `action_smuggle`, `movement_smuggle` | 1e-4 (м) |

Полей мяча в таблице нет намеренно: `B`-строки в вердикт фазы 5 не входят. Порт ставит мяч из этой же
строки с нулевым моментом, а у эталона мяч в тот же тик может катиться после кикоффа — сравнение дало бы
гарантированный «рост» по `ball_mom_*` на каждом прогоне, то есть ровно тот шум, против которого заведён
белый список. Дифф читает `B`-строки только чтобы посчитать дистанцию до мяча (проверка безопасной
области). Мяч войдёт в вердикт на фазе 8, вместе с касаниями.

**Начало роста — операционально:** первый тик `T`, для которого `|Δ(T)|` уже больше допуска класса,
и на окне `K = 10` последующих тиков `|Δ|` не убывает ни разу, а `|Δ(T+K)| >= 2·|Δ(T)|`. Определение
обязано быть именно таким, а не «на глаз»: иначе тест на этот пункт проверяет собственную формулировку
и ничего не гарантирует.

**Blocked by:** 05 — надстраивается над тем же инструментом и тем же отчётом.

- [x] Непрерывные поля сравниваются с допуском своего класса; допуски переопределяются файлом.
      Формат файла — `<ключ> <число>`, ключи `position`/`angle`/`velocity`/`smuggle`/`window`, `#` —
      комментарий; неизвестный ключ валит парсер с указанием строки. Шестой (необязательный) аргумент
      `tools/trace_diff.gd`; без него действуют дефолты из инструмента
- [x] Расхождение в пределах допуска: инструмент молчит. Проверено постоянным |Δ| = 0.0005 при
      допуске позиции 1e-3 — вердикт `match`, поле помечено «в шуме»
- [x] Растущее расхождение по правилу `K = 10` / `×2`: назван тик начала роста, а не первое
      превышение. Проверено рядом |Δ| = 0.002·(t−19) с тика 20 → назван тик 20. Тот же ряд с
      допуском 1e-2 из файла даёт тик 25 — значит файл действительно подставляется в правило
- [x] Одиночный всплеск того же размера началом роста не считается. Проверено всплеском 0.022 (пик
      растущего ряда) на одном тике → «в шуме», наибольшее |Δ| при этом печатается
- [x] Дискретный слой остаётся главным: при расхождении дискретного поля отчёт начинается с него, но
      непрерывный слой считается на всей длине трассы, а не до тика `T`. Проверено синтетикой
      (дискретное с тика 5, рост с тика 20 — назван и тик 5, и тик 20, дискретный блок первым) и на
      реальной паре, где дискретное расхождение стоит на тике 0
- [x] Белый список действует и на непрерывные поля: поле с правилом печатается как «исключено белым
      списком», остальные непрерывные продолжают сравниваться
- [x] Отчёт по-прежнему помещается на экран: по каждому непрерывному полю ровно одна строка — тик
      начала роста либо «в шуме». Реальный отчёт с обоими слоями — 34 строки, синтетический худший
      случай — 35, ни одной строки шире 120 символов
- [x] `tests/check_trace_diff.gd` дописан шестью проверками: в пределах допуска, рост по правилу

      непрерывном поле, первенство дискретного слоя. Пороги заданы в тесте числами, а не чтением
      константы из инструмента. `CHECK PASS`

## Решение, которого не было в тексте тикета

**Растущее расхождение делает код возврата ненулевым — заведён вердикт `drift`.** Раньше `match`
означал «дискретные поля совпали» и давал `0`. Слой, который ловит ошибки, не меняющие выбор клипа,
был бы бесполезен в скрипте, если бы при находке инструмент выходил нулём; спека же требует ненулевого
кода «при любом расхождении». Теперь `0` — оба слоя чисты, `1` — в том числе рост непрерывного поля.

**Окно правила роста отсчитывается по спаренным тикам, а не по номерам тиков.** У эталона законно
бывают тики без контролируемого (стандарты), и по номерам окно рвалось бы на каждом из них. Следствие,
принятое сознательно: расхождение, начавшееся ближе `window` тиков к концу трассы, началом роста не
объявляется — окна для проверки нет.

**Формат файла допусков выбран по образцу заголовочных директив сценария** (`seed 20260731`), потому
что спека его не задаёт, а другой формат в проекте пришлось бы выдумывать.

**«В шуме» печатается вместе с наибольшим наблюдённым |Δ|.** Без числа строка скрывала бы поле, которое
допуск превышает, но не растёт монотонно, — и это не гипотеза: на реальной паре `rel_body_angle` даёт
макс |Δ| 0.785 при допуске 0.001 и при этом честно «в шуме».

## Что показал реальный прогон

На урезанной до переезда контроля паре (`walk_line`, тики 0–420) непрерывный слой называет
`pos_y` и `move_y` с тика 4, `pos_x` с тика 45, `angle` с тика 403; `pos_z`, `move_z` и оба смаггла —
ровно нули. Это следствие уже известного расхождения тика 0 (тикет 10: разные idle-клипы → разное
движение корня), а не новая находка: первый разошедшийся тик по определению есть место первого
отступления. **Новых тикетов не заводится.**
