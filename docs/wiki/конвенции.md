# Конвенции: «грабли, о которые убьёшься»

## InputMap строится программно

`match_manager.gd:_setup_inputs()` **стирает и пересоздаёт** каждое действие в `_ready()`. Биндинги в
`project.godot` перекрыты и фактически мертвы. **Всегда правь `_setup_inputs()`, никогда input в
`project.godot`.**

Движение — **стрелки / левый стик** (буквы WASD освобождены под действия):

| Действие | Клавиша | Пад |
|---|---|---|
| Удар (заряд/отпуск) | `D` | X |
| Короткий пас | `X` | A |
| Пас на ход | `W` | Y |
| Навес | `A` | B |
| Контекст (модификатор комбо / swap) | `Q` | LB |
| Модификатор кручёного удара (curl) | `E` | RB |
| Спринт | `Shift` | RT (аналог) |
| Пауза | `Esc` | Start |
| Камера broadcast / 3-е лицо | `1` / `3` | — |
| Смена ноги (стандарты) | `L` / `R` | — |

Дебаг-клавиши стандартов: **P** пенальти, **Alt+K** пенальти в наши ворота, **F** штрафной, **C**
угловой, **G** ввод от ворот, **T** вброс (`throw_in_debug`; клавиша `T` также = `corner_call` в контексте
углового), **O** кикофф. См. [[пас]], [[стандарты-и-intent-seam]].

## Что ещё легко перепутать

- **Движение — velocity + `move_and_slide()` через [[локомоция|PlayerMotor]]**, прямого сдвига позиции
  для локомоции нет. Единственное исключение — слайд [[подкат-и-падение|подката]] (`move_and_collide`).
- **Дриблинг — непрерывное lead-follow** (мяч впереди, дистанция растёт со скоростью; вырвался → догон).
  Полная модель — [[мяч-и-дриблинг]]; `SPRING_*`/`DRIBBLE_FORWARD_DIST` — легаси. Игнорируй описание
  пружины в OPENCODE.md.
- **Удар/пас — deferred-impulse (commit-action)**, не прямой `ball.kick()`. Резолвинг — `ActionExecutor`,
  ждёт `action_contact` анимации. Хелперы менеджера объявляй с явным типом, `:=` не компилируется
  (`_manager` типа `Node`). См. [[пас]].
- **Движение камера-относительно** — ввод через `camera_pivot.global_transform.basis`. См. [[поле-и-камера]].
- **Управляемый игрок** авто-переключается на дриблящего team_1; `Q`/`LB` вручную — **только без владения**
  (`_we_possess()`), с `_manual_swap_cooldown`. Cyan-конус — управляемый, жёлтый (при заряде паса) —
  цель авто-аима.
- **Команды — через группы** `team_1`/`team_2` (+ временная `fallen`). Используй `_same_team()`/группы,
  не идентичность узла.
- **Диффай baseline ошибок headless по категории/тексту, не по счётчику** (см. [[архитектура]]).
- **Порт GameplayFootball: GDScript↔C# мост через `load("res://....cs").new()`.** `var x := ...` не
  выводит тип из `Variant`-результата C#-метода (парсинг падает — объявляй тип явно, `var q: Quaternion
  = anim.SampleRotation(...)`); мост не переносит C#-дефолт-аргументы (`AnimationApplier.Apply` зовут
  из GDScript только полным списком из 6 аргументов). Плюс C#-специфика: `Gpf.Animation` затеняет
  `Godot.Animation` при `using Godot;` вне `namespace Gpf` — пиши полное `Gpf.Animation`. См.
  [[порт-gameplayfootball]].
- **Флейки headless-тесты.** `check_keeper_clear.gd`, `check_keeper_no_rush_on_pass.gd` — физика/тайминг,
  ~1 из 2–5. Целое семейство launch-зависимых flow/intent-тестов (`check_corner_intent.gd`,
  `check_goal_kick_intent.gd`, `check_setpiece_kicker_no_touch.gd` и подобные) может выдать
  `released=true launched=false`, когда анимация не дошла до контакт-кадра в бюджет. Независимо от кода —
  **перезапусти 2–3× перед тем, как счесть провал регрессией.**

## Отладочные флаги (`football_constants.gd`, все `false`)

- `DEBUG_DISABLE_OPPONENT` — ИИ-соперник стоит + стенки болванок (тест дриблинга/ударов).
- `DEBUG_MARK_TEAMMATE` — соперник маркирует ИИ-тиммейта (тест пасов/перехватов).
- `DEBUG_DISABLE_TEAMMATE` — тиммейт не спавнится (1-в-1 + вратарь).
- `DEBUG_BALL_TRAIL` — цветной след за мячом (траектории).

Debug-строительство (file-logging, `[KEEPER]`/`[MATCH]`/`[REFEREE]`/`[BALL]` принты) **снято перед
merge**. Старая хардкод-камера вратаря заменена постоянным переключателем `1`/`3`.
Подробности — `docs/debug-tools.md`.
