# Модель мяча: future refactors (по триггеру)

**Дата:** 2026-07-11
**Контекст:** Фаза 0 фичи ударов мигрирует мяч на модель OpenSoccer (всегда-столкновение +
импульсный дриблинг) низко-рисковой стратегией — см.
[план Фазы 0](../plans/2026-07-11-shot-system-phase0-ball-model.md) и
[спек](../specs/2026-07-10-shot-system-design.md). План намеренно отклоняется от буквы спека в трёх
местах ради снижения риска. Этот документ фиксирует, **что это за отклонения, стоит ли их снимать
и когда** — чтобы будущие сессии видели намеченный путь и не рефакторили спекулятивно.

## Принцип

Рефакторим **по триггеру, а не заранее** (YAGNI). Все три отклонения спрятаны за одним швом —
стейт-машиной мяча и функциями `set_dribbler`/`release_dribble`/`state`. Пока весь код входит во
владение через этот шов, внутренности за ним меняются локально, без правки потребителей. Фаза 0 —
это **правильный фундамент с чистым швом**, а не времянка.

**Важно:** OpenSoccer — не эталон архитектуры, а референс идей (импульсный трап, Magnus,
`SaveArea`). В его `SmartBall.gd` много мёртвого кода и размазанного состояния. Правильный «север» —
не «как в OpenSoccer», а **консистентно этому проекту** (intent-based компоненты как `PlayerMotor`,
чистые функции-системы как `PassSystem`) и **масштабируемо к 11v11**.

## Отклонение A — переименовать `dribbler` → `player`/`possessor`

**Сейчас:** публичный API владения оставлен как `set_dribbler()`/`release_dribble()`/`dribbler`
(тонкие обёртки над стейт-машиной), чтобы `simple_ai.gd`/`teammate_ai.gd`/`match_manager.gd` не
меняли ~20 мест обращения.

**На перспективу:** имя `dribbler` вводит в заблуждение при полной стейт-машине — у летящего мяча
нет дриблёра, у пойманного вратарём — тоже. Переименовать в `player`/`possessor` + убрать легаси.

**Ценность:** ясность. Почти нулевой риск (механический find-replace по 4 файлам).

**Триггер:** **сразу после стабилизации Фазы 0 вживую.** Делать рано — самый дешёвый из трёх.

**Объём:** find-replace `dribbler`→`possessor` в `ball_controller.gd`, `simple_ai.gd`,
`teammate_ai.gd`, `match_manager.gd`; удалить геттер-обёртку `player()` (станет самим полем).

## Отклонение B — внешний `ball.dribble(intent)` вместо самоуправления

**Сейчас:** мяч сам тянется за владельцем внутри `_integrate_forces` (читает
`dribbler.global_position`). Импульсная математика уже на месте, но драйв — изнутри мяча.

**На перспективу:** это место, где OpenSoccer прав по сути — и даже больше, это **совпадает с
философией проекта**. Уже есть `PlayerMotor.set_move_intent(dir, speed)`: контроллеры не двигают
тело напрямую, а сообщают намерение. Идеально-консистентный ball-аналог — `ball.dribble(intent)`,
вызываемый владельцем каждый кадр, а не мяч, лезущий в позицию игрока. Открывает «разные игроки
ведут по-разному» (скорость/ловкость/близкий контроль — как OpenSoccer масштабирует от `pAgility`).

**Ценность:** пер-игроковый дриблинг, чистая развязка (мяч перестаёт знать про внутренности игрока),
консистентность с `PlayerMotor`.

**Триггер:** когда появятся **характеристики дриблинга у игроков** (стата) **или** всплывёт проблема
контроля, которую самоуправляемая ветка не решает. До этого — лишняя связь (3 контроллера обязаны
звать `dribble()` каждый кадр) без выигрыша.

**Объём:** добавить `ball.dribble(intent)`; вызовы в человек-вводе (`match_manager`), `simple_ai`,
`teammate_ai`; удалить самоуправляемую ветку `TRAPPED` из `_integrate_forces`. Реализовать в
проектно-консистентной форме (intent), **не** копируя код OpenSoccer буквально.

## Отклонение C — `TrapArea` (Area3D) вместо дистанционного подбора

**Сейчас:** используется существующий дистанционный подбор (`dist < 1.0` → `set_dribbler`) + гейт по
скорости мяча. Функционально эквивалентно трап-зоне радиуса 1 м, но без нод/сигналов.

**На перспективу:** `TrapArea` даёт две вещи, нужные позже: **направленную зону-конус впереди
игрока** («лучше контролируешь мяч, когда повёрнут к нему»; first-touch/приём) и работу через
физический broadphase вместо O(N)-цикла по всем игрокам.

**Ценность:** направленный трап/первое касание; масштаб на 22 игрока.

**Триггер:** движение к **11v11** **или** фича **«первое касание/приём»**. Средняя ценность, не срочно.

**Объём:** навесить дочерний `Area3D` (`TrapArea`, конус впереди) в `_setup_*`-функциях спавна;
заменить дистанционную проверку в `_handle_dribbling()` на `body_entered`/`get_overlapping_bodies`.

## Рекомендованная последовательность

1. **Сейчас:** Фаза 0 (низко-рисковая) → приземлить, оттюнить ощущение вживую.
2. **Сразу после:** Отклонение **A** (переименование) — ясность, ~нулевой риск.
3. **Фазы 1–3** фичи ударов поверх стабильного фундамента.
4. **При добавлении статы игроков / 11v11:** Отклонение **B** (`ball.dribble(intent)`), затем **C**
   (`TrapArea`).

Из трёх реально целить стоит только в **B** (в форме `ball.dribble(intent)`, не буквально код
OpenSoccer); **A** — про ясность независимо от OpenSoccer; **C** — по мере роста ростера.
