# Трекер задач: локальный markdown

Задачи и спеки (спека = PRD) этого репозитория живут markdown-файлами в `.scratch/`.
GitHub Issues репозитория `Churikov0112/open_football` под задачи **не используются** (и `gh` CLI
в системе не установлен) — не пытайся звать `gh issue create`.

## Конвенции

- Одна фича — один каталог: `.scratch/<feature-slug>/`
- Спека — `.scratch/<feature-slug>/spec.md`
- Тикеты реализации — по файлу на тикет: `.scratch/<feature-slug>/issues/<NN>-<slug>.md`,
  нумерация с `01`. Никогда не один общий файл со списком тикетов.
- Состояние триажа — строкой `Status:` у верха файла тикета (строки ролей — в
  `triage-labels.md`).
- Комментарии и история обсуждения дописываются в конец файла под заголовком `## Comments`.

Литералы формата (`Status:`, `Type:`, `Blocked by:`, `## Comments`, `## Answer`) —
**английские**: их читают скиллы, это часть формата файла, а не проза. Всё остальное содержимое
пиши по-русски, как и прочие доки проекта.

## Когда скилл говорит «опубликуй в трекер»

Создай новый файл под `.scratch/<feature-slug>/`, заведя каталог, если его нет.

## Когда скилл говорит «возьми нужный тикет»

Прочитай файл по указанному пути. Обычно пользователь передаёт путь или номер тикета напрямую.

## Операции wayfinder

Используются скиллом `/wayfinder`. **Карта** — файл, у которого по **дочернему** файлу на тикет.

- **Карта**: `.scratch/<effort>/map.md` — тело из Notes / Decisions-so-far / Fog.
- **Дочерний тикет**: `.scratch/<effort>/issues/NN-<slug>.md`, нумерация с `01`, вопрос в теле.
  Строка `Type:` фиксирует тип тикета (`research`/`prototype`/`grilling`/`task`), строка
  `Status:` — `claimed`/`resolved`.
- **Блокировки**: строка `Blocked by: NN, NN` у верха файла. Тикет разблокирован, когда каждый
  перечисленный файл в состоянии `resolved`.
- **Фронтир**: просканируй `.scratch/<effort>/issues/` на файлы открытые, разблокированные и
  незанятые; побеждает первый по номеру.
- **Занять**: поставь `Status: claimed` и сохрани до начала любой работы.
- **Закрыть**: допиши ответ под заголовком `## Answer`, поставь `Status: resolved`, затем добавь
  указатель на контекст (суть + ссылка) в Decisions-so-far карты `map.md`.

## Отношение к вики и логу

`.scratch/` — это **работа в процессе**, а не слой документации. Когда задача закончена, итог
переезжает по правилам `CLAUDE.md`: состояние подсистемы — на страницу `docs/wiki/`, веха —
строкой в `log.md`. Каталог фичи в `.scratch/` после этого не является источником истины.
